## 공유 인코딩 1,000명 — 한 시간 실측 기준

공개 계산기는 **1,000명·3,600초 실측**과 이전 300명 표본을 분리한다. 작성자 20명·이동 80명·독자 900명, 광장 출발 25%, 추가 압축 없음에서 WebSocket 프레임 포함 **1,195,379 B/s**, 평균 **0.3627코어**, 시간 가중 RSS **1.0728GiB**였다. 약 36만 행동을 모두 처리했고 접속을 3,000회 교체했다. [검증 범위와 원자료](SINGLE_SERVER_1000.md)

이 수치는 `a2cd85a`의 공유 인코딩·신선도·전달 경로를 실제 한 시간 실행한 값이다. 이후 CJK 경계와 긴 치환의 관객까지 과부하 비용에 포함한 최종 방어는 별도 정상·급증·공개 시험으로 검증한다. 마지막 변경까지 같은 한 시간 표본에서 측정했다고 간주하지 않는다. 초기 상태의 3분 표본은 송신 1.50MB/s였으며, 한 시간의 1.20MB/s와 차이가 있다. 시작 글자·관측 상태·이동에 따른 변화까지 포함한 **이 활동 시나리오의 평균**이다. 다른 활동률·밀집도·무입력 축소 구간의 원가를 같은 값으로 보장하지 않는다.

## CDN 적용 — 2026-11-26

Railway CDN을 활성화했다. 해시 JS·CSS·글꼴과 HTML·공개 고정 안내의 실제 edge HIT를 확인했지만 **전체 방문자의 장기 byte hit ratio는 미측정**이다. 기존 단일 위치 반복 요청의 적중률을 비용 모형의 실측값으로 쓰지 않는다. 공개 계산기는 `CDN이 처리하는 정적 전송량 비율`을 가정 입력으로 제공하고 기본 0%를 유지한다.

기존 300명·20분 체류·20% 글꼴 다운로드 가정에서 `C(h) = 78.3729 + 13.7352 × (1-h)` USD/30일이다. `h`는 브라우저 캐시를 거친 뒤 실제로 요청되는 정적 **바이트** 중 edge에서 제공하는 비율이며 요청 건수 비율이 아니다. `h=0`은 $92.11, **h=0.95 가정은 $79.06**이다. CPU/RSS와 실시간 바이트 실측은 유지하고 CDN이 처리한 정적 egress에만 무료 정책을 적용한다. 캐시 miss·새 edge·배포 새 파일·만료가 있어 100% 적중을 보장하지 않는다. 자산 보관용 볼륨 증분과 새 빌드의 메모리는 이 수식에 별도로 재실측하지 않았다.

해시 번들 적용 직후 지도 페이지/JS/CSS gzip 본문은 33,682 B로 이전 49,206 B보다 작다. 기존 비용 표와 계산기는 이 이전 실측을 보수적으로 유지한다. 글꼴 바이트는 같고 CDN은 브라우저가 받아야 할 파일 크기를 줄이는 기술이 아니다. [캐시/배포 정책과 측정](CDN.md) · [공개 최초 점검](measurements/cdn-2026-11-26/first-public.json)

### 가정과 민감도

평균 동접 300명이 하루 종일 유지되고 방문당 20분이면 30일에 648,000회 방문한다. 방문마다 압축된 지도 자산을 받고 그중 20%에서 혼합 시야 실측 분량의 글꼴을 새로 받는다고 가정했다. 304·캐시 재사용의 페이지 절감은 반영하지 않았다. 이 언어 분포는 실제 이용자 통계가 아니다. 방문 중 새로운 문자 범위를 읽으면 추가 파일이 필요하다. 같은 조건에서 모든 글꼴 조각을 받는다고 가정하면 기본 30일 비용은 **$118.52**다. 계산기에서 평균 체류와 폰트 캐시 비율, 시간대별 밀집도를 바꿀 수 있다. 시간대 조합은 분산·밀집 시험의 두 **단가**를 가중한다. 붐비는 시간이 6시간인 것과 동접자의 25%가 같은 광장에 있는 것은 서로 다른 배치다. 실제 고객 송신에 붙는 프레임·TLS·재전송, 플랫폼 할인·크레딧·최소 구독료, 세금·백업·다른 서비스는 추정 밖이다.

기술적으로 유지 가능한 동접과 예산으로 유지할 수 있는 이용시간은 별도로 판단한다. 당시 워크스페이스 한도는 알림 $50, 하드 $100였다. 기본 혼합 시야 가정은 $100 아래지만 전체 문자 범위를 읽거나 광장 활동이 많아지면 넘는다. 새 모형이 지출 상한을 보장한다는 뜻은 아니다. 300명이 하루 종일 유지되는 달에는 위 비용과 워크스페이스 전체 사용량을 함께 확인해야 한다. 300명 밖의 처리량이나 원가 곡선은 이 실측으로 확정할 수 없다.

### 기본값에서 바로 쓰는 식

월은 30일, 평균 체류는 20분이다. 동시에 머무는 사람의 2%가 초당 3번 입력하고 8%가 10초마다 좌표를 5번 갱신한다. 하루 6시간 동안 접속자의 25%가 붐비는 광장들에 있고, 나머지 시간과 사람은 일반 지역에 분산된다고 둔다. 여기서 한 광장은 서로의 화면이 상당 부분 겹치는 무리다. 같은 지명을 쓰더라도 서로의 글을 볼 수 없는 무리는 따로 센다.

```text
x = 평균 동접 / 1,000
g = 붐비는 시간에 광장 방문자 한 명이 같은 광장에서 만나는 다른 사람 수의 평균
30일 사용료(USD) ≈ 1.20 + x × (63.93 + 8.11 × g / 249)
```

250명씩 여러 광장이 생기면 가득 찬 광장에서는 g가 249로 유지되고 평균 동접 1,000명이 늘 때 월 약 $72가 추가된다. 접속자의 25%가 언제나 같은 광장에 모이면 g는 대략 0.25 × 동접 − 1이 된다. 활동 비율이 일정할 때 글·이동을 만드는 사람과 그걸 보는 사람이 같이 늘어 비용에 동접의 제곱 항이 생긴다. 독자만 늘고 작성·이동 총량이 같다면 이 제곱 가정은 과하다.

| 평균 동접 | 여러 광장에 최대 250명씩 | 한 광장에 전체의 25% | 여러 광장에서 이용 1,000시간당 |
| ---: | ---: | ---: | ---: |
| 100 | $8 | $8 | $0.107 |
| 1,000 | $73 | $73 | $0.102 |
| 10,000 | $722 | $1,454 | $0.100 |
| 100,000 | $7,205 | $87,787 | $0.100 |

1,000명 이하는 광장에 오는 사람이 최대 250명이어서 두 배치가 일치한다. 10만 명은 기울기의 차이를 보여주는 외삽이다. 현재 한 대의 처리량, 세계 크기 상한 이후의 공간 밀도, 추가 서버 수와 단가는 이 표로 검증할 수 없다.

#### 압축 배수의 비교점

현재 서버 코드로 1,000개 로컬 연결을 열고, 분산 45초·광장 90초 동안 실제로 받은 WebSocket 메시지의 약 1/64을 독립적으로 표집했다. 메시지마다 사전 공유 없이 raw DEFLATE 레벨 3을 적용하고 원문이 더 작으면 원문 크기를 택했다. 압축한 메시지는 각각 풀어 바이트가 같은지 확인했다.

| 배치 | 표본 메시지 | 원문 바이트 | 선택 후 바이트 | 크기 감소 배수 |
| --- | ---: | ---: | ---: | ---: |
| 분산 | 1,369 | 3,336,820 | 1,058,894 | 3.15배 |
| 광장 | 1,496 | 15,823,577 | 4,044,067 | 3.91배 |

합성 입력은 한글 ‘한’, 공백, 줄바꿈 중심이었다. 광장 시험에서는 교체 접속 50회가 제한 시간을 넘겼다. 전송 헤더·TLS·실시간 압축 CPU·다양한 실제 문장은 이 오프라인 비교 범위 밖이다. 기본값의 8배와 P2P 절감률은 아직 측정하지 않았다. 동접 1,000명에서 **8배 + 독자 전달 $73, 8배 + 서버 전달 $109, 4배 + 서버 전달 $193**으로 바뀐다. 모두 같은 정적 자산·서버 최적화를 가정한 수치다.

### 일반식과 사업 지표

`h`는 광장이 붐비는 하루의 비율이다. 해당 시간 각 광장 인원을 `nᵢ`라 두고 `P = Σ nᵢ(nᵢ−1) / (250×249)`로 놓는다. 대략적인 추가 수신자 수를 표현하기 위해 분산·광장 실측 차이를 이 값에 비례시켰다. 두 실험은 자동 확장·접속 이탈도 달라서 그 차이 전부를 순수한 광장 효과로 식별한 것은 아니다. 계산기는 250명씩 나눈 뒤 남은 한 광장의 인원도 따로 센다.

```text
x = 평균 동접 / 1,000
K = 실시간 데이터 축소 배수
d, p = 분산 기본분과 광장 추가분 각각의 유료 송신 순절감률
실시간 전송 = [519.62 × x × (1−d) + 617.10 × h × P × (1−p)] / K
서버 사용   = 1.20 + 0.5 × (17.72 × x + 10.86 × h × P)
정적 전송   = 12.854 × x
월 사용료   = 실시간 전송 + 서버 사용 + 정적 전송
```

일중 동접 변동이 크면 시간대별 동접과 광장 인원에 위 식을 적용해 시간 비중으로 평균낸다. 몰리는 시간대에는 동접의 제곱의 평균이 평균 동접의 제곱보다 클 수 있다. 피크로 인해 필요한 추가 상시 설비 비용은 별도 항으로 더한다.

30일 총 이용시간은 `720 × 평균 동접`, 총 방문 횟수는 이 가정에서 `2,160 × 평균 동접`이다. 월 사용료를 총 이용시간 또는 방문 횟수로 나누고 1,000을 곱하면 각각의 인프라 손익분기 순매출을 얻는다. 예를 들어 순매출이 이용 1,000시간당 $1이라면 평균 동접 10만 명의 월 순매출은 $72,000이다. 위 표에서는 분산 시 인프라비를 충당하고, 한 광장 집중 시 인프라비가 순매출보다 크다. 수익률 판단에는 실제 순매출과 나머지 영업비용을 넣는다.
