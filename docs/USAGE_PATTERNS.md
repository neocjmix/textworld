# 공개 이용 패턴을 읽는 법

운영자는 같은 시간대의 **참여 방식, 시야의 혼잡도, 서버 비용과 체감 지연**을 함께 볼 수 있다. 예를 들어 동접이 같은 두 시간 중 한쪽에서만 쓰기 거절이 늘었다면, 그 시간의 편집 비중과 한 번의 입력이 영향을 주는 관측자 수를 확인할 수 있다. 보고서는 Railway의 기존 계측 DB를 읽는다.

## Grafana에서 보기

[운영 대시보드 열기](https://grafana-production-7d77bc6c.up.railway.app/d/textworld-usage)

운영자 계정은 `admin`이다. 초기 비밀번호는 [Railway의 grafana 서비스 변수](https://railway.com/project/c702f64c-3e82-47e8-9945-e0540b1b5b2b/service/8cd5165b-3193-45f9-ac8b-ae73fc355a3c/variables?environmentId=dcf0285c-151d-4a4a-ac7a-37efab3fcb0d)에서 `GF_SECURITY_ADMIN_PASSWORD`를 열어 확인한다. Grafana 안에서 변경한 뒤에는 변경한 비밀번호로 로그인한다.

기본 화면은 최근 1시간이며 1분마다 갱신한다. 패널 하나에 마우스를 올리면 다른 그래프에도 같은 시각이 표시된다. 공개 접속·HTTP/MCP·시험 봇이 얼마나 있었는지 확인한 뒤 공개 시야 안 인원, 혼잡에 따른 쓰기 429, 입력 지연을 비교한다. 지연은 표본의 p95 상한이다. 쓰기 429는 구간 합계이므로 서로 다른 해상도의 건수를 비교할 때는 구간 길이도 고려한다.

최근 6시간 이내는 분 단위, 최근 30일 안의 최대 14일 범위는 시간 단위, 그 밖의 보존 구간은 일 단위로 읽는다. UTC 구간을 브라우저의 현지 시각으로 표시한다. 0은 관측한 0건이며, 빈 구간은 미계측 또는 해당 지표의 표본 없음이다. 같은 UTC 구간에 배포가 둘 이상이면 계측된 배포의 원래 히스토그램을 병합한다. 배포별 비교에는 아래 운영 보고서를 쓴다.

Grafana의 Infinity 플러그인이 Railway 내부망에서 기존 운영 API를 인증해 조회한다. 모든 패널이 요청 한 번의 결과를 공유한다. 원본은 Textworld의 계측 SQLite에 있고, Grafana의 1GiB 볼륨은 로그인·설정에 사용한다. 대시보드와 데이터 소스의 정의는 [Grafana 배포 파일](../observability/grafana/)에서 버전 관리한다.

## 운영 보고서

```sh
# 운영자 토큰을 가진 환경에서 실행. 기본값은 공개 서버의 최근 24개 UTC 시간 구간.
npm run --silent metrics:usage
# 피크의 한 시간, 분 단위. until을 생략하면 현재 시각까지.
npm run --silent metrics:usage -- --period 60 --hours 1 --until 2026-11-27T10:59:59Z --json
# 최근 30개 UTC 날짜의 추세
npm run --silent metrics:usage -- --period 86400 --hours 720
# 같은 해상도로 보관한 export에서도 재현 가능
npm run --silent metrics:usage -- --file artifacts/metrics-export.json --period 3600 --hours 24 --json
```

표 앞부분의 합계는 배포와 운영 시험 혼재 여부가 같은 구간끼리 원래 히스토그램을 병합해 계산한다. 아래에는 각 시간대의 표본을 보여준다. JSON에는 분모·표본 수·분포와 전송량도 들어 있다. 시간대는 UTC이며 출력 범위는 구간 시작 시각 기준이다. 마지막 구간은 진행 중일 수 있다. `coveredBuckets / expectedBuckets`와 각 행의 `measuredSeconds`로 실제 수집 범위를 확인한다. 보존 한도를 넘긴 구간과 기능 도입 이전은 미계측이다. 표의 대시는 분모나 지연 표본이 없다는 뜻이다.

### 세션과 행동의 기준

- `public_ws`는 공개 소켓으로 들어온 참여자이며 외부 자동화도 포함한다. `agent_api`는 HTTP와 이를 사용하는 MCP, `playtest`는 서버가 직접 연 전용 시험 소켓이다. 표시 이름·헤더로 출처를 선택할 수 없다. `includesPlaytest`가 참인 구간은 시험과 공개 이용이 함께 만든 서버 부하다.
- 종료 세션을 **관찰만 / 이동만 / 편집했으나 첫 글 없음 / 작성** 중 하나로 센다. 첫 글 작성률의 분모는 같은 기간에 종료한 세션 수다. 진행 중인 세션은 체류 시간 비중에 계속 반영되고 종료 지표에는 나중에 들어온다. 재접속은 새 세션이며 HTTP/MCP에서 떠나기를 생략하면 유휴 만료까지 접속 시간에 포함된다. 프로세스가 강제 종료된 순간 열려 있던 세션은 종료 통계에서 빠질 수 있다.
- 쓰기·삭제는 서버가 실행한 작업 단위다. 한글 조합, 여러 글자 붙여넣기, API의 속도 제한을 적용한 분할 쓰기는 물리 키 입력 수와 다를 수 있다. 승인된 같은 작업의 재전송을 중복 합산하지 않는다. 이동은 실제 주소가 바뀌었을 때 센다. 첫 위치로 가기·줄바꿈 등도 이동을 만들 수 있다.
- 행동 429는 서버의 참여자·네트워크 예산과 전역 작업량 예산이 내린 **정책 결정 수**다. 관측·분류할 수 없는 요청은 `other`다. HTTP/MCP는 한 요청에 여러 행동이 들거나 이미 일부를 실행할 수 있다. HTTP 응답 상태 수는 기존 경로 지표에서 따로 본다.
- SQLite에는 고정된 지표별 수·합·최솟값·최댓값·히스토그램만 남는다. 글, 좌표, IP, 이름, 토큰, 세션 ID, 기기 식별자를 행동 통계에 기록하지 않는다. 고유 방문자·재방문율을 계산할 수 없다. p95는 히스토그램 경계의 상한이다.

### 공개 뒤 실험을 바꾸는 순서

1. 운영 시험이 섞이지 않은 첫 주를 시간 단위로 본다. 평균 동접이 비슷한 구간에서 작성률, 행동 간격, 시야 안 타인 수, 피크의 쓰기 거절이 어떻게 달라지는지 찾는다. 표본 수와 누락 시간을 함께 남긴다.
2. 평상시와 가장 혼잡한 시간대를 각각 하나씩 골라 실제 작성자·이동자·관찰자 비율, 접속 교체와 글 묶음 길이를 유한 수명의 시험 러너에 적용한다. 첫 글 작성률은 종료 세션 기준이므로 순간 동접의 작성자 비율은 편집 활동 시간 비중도 함께 사용한다.
3. 같은 조건의 변경 전후에서 행동 승인량·429·지연·CPU·공개 WS 송신량을 비교한다. 세계의 성장·축소·풍화와 신규 입장의 영향도 같이 본다. 운영 상한 변경과 비용 예측의 근거로 삼을 때는 해당 부하를 실제로 재현한다.

## 배포 검증 · 2026-11-27

Railway에서 두 브라우저와 재접속 한 번을 실행했다. 운영 보고서에서 종료 세션 3건, 작성자 세션 1건, 승인된 쓰기 2건을 확인했고 같은 1분을 내보낸 파일에서도 재현했다. 별도 브라우저 방문의 가시성 시간도 다음 분 집계에 도착했다. 이 수치는 운영자가 만든 검증 표본이다.

로컬에서는 같은 시드·실제 시계·초기 글 6,000자의 세계에서 300명(작성 6, 이동 24, 정지 270)을 150초씩 실행했다. 1차는 기존 코드 다음에 계측 후보를, 2차는 배포한 계측 다음에 기존 코드를 실행했다. 매회 4,514건 모두 승인, 38회 접속 교체, 예기치 않은 종료와 관측 순번 누락은 0건이었다.

| 실행 순서 | 입력 ACK p95 | 타인 수신·해독 p95 | 평균 프로세스 CPU | 평균 RSS |
| --- | ---: | ---: | ---: | ---: |
| 기존 코드 | 5.5ms | 55.1ms | 0.099코어 | 335MiB |
| 행동 계측 후보 | 5.6ms | 55.4ms | 0.095코어 | 400MiB |
| 배포한 계측 | 6.1ms | 56.0ms | 0.103코어 | 328MiB |
| 기존 코드 재실행 | 5.6ms | 55.5ms | 0.094코어 | 381MiB |

이 조건에서 처리량과 연결 품질을 확인했다. RSS가 실행마다 달라 실제 비용은 공개 피크 시간대에 프로세스와 Railway 컨테이너를 함께 관찰한다. 300명 공개 상한을 사용한다. [실험 조건과 계측 수치](measurements/public-usage-2026-11-27.json)
