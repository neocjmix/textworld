# 확장·축소를 일상적인 사건으로 처리하기

2026-11-03. 이전의 전역 epoch 입력 중단 규칙을 폐기한다. 크기 변경은 입력·이동 사이에 일어나는 세계 사건이며, 참여자는 **보정된 현재 커서에서 다음 행동을 계속한다.** 글이나 문장을 하나의 좌표계 안에서 보존할 의무는 없다. 제품 헌법은 수정하지 않았다.

## 두 종류의 원자성을 혼동했다

이전 설계는 DB의 일관성과 사용자의 입력 중단을 묶었다. 셀·크기 메타데이터가 서로 다른 좌표계로 저장되지 않아야 한다는 요구에서, 조합 취소·미확정 입력 폐기·봇 turn 중단까지 도출한 것은 과했다. 세계의 비영속성은 이미 제품 원칙이다.

단일 writer가 `입력 → 재배치 → 입력` 순서로 처리하면 충분하다. 재배치 전 입력은 재배치 대상이 되고, 뒤에 도착한 입력은 보정된 커서에서 실행한다. 실행 중인 봇의 여러 글자는 그 사이에 재배치가 끼어들 수 있다. 문장 전체의 성공·실패나 이전 모양 복구를 약속하지 않는다.

SQLite의 짧은 저장 트랜잭션은 유지한다. 저장 실패·프로세스 중단 뒤 크기와 셀이 반쪽씩 남는 것을 막는 내부 장치다. 한 번의 CJK 치환도 두 칸과 삭제 범위를 함께 반영한다. 이를 위해 참여자를 멈추거나, 조합 종료를 기다리거나, 분산 잠금을 도입하지 않는다. 동기 전체 remesh가 이벤트 루프를 점유하는 비용은 여전히 별도 문제다.

## 비교한 모델

| 모델 | 판단 |
| --- | --- |
| 전역 epoch가 바뀌면 모든 입력 취소 | 절대 좌표 요청에는 명확하지만, 먼 지역의 성장까지 입력 중단으로 확대한다. 사용자 인터랙션에서는 폐기한다. |
| epoch 검사만 제거하고 옛 절대 좌표 사용 | 옛 숫자가 새 세계의 다른 칸을 가리킨다. 조합 치환·삭제 대상도 달라지므로 기각한다. |
| 과거 좌표계의 요청마다 변환 이력을 따라가기 | 지연 요청 수명·이력 보관·중복·범위 권한을 함께 관리해야 한다. 현재 커서로 표현할 수 있는 행동에 불필요한 비용이다. |
| 영구 셀 ID 또는 지역 패치 그래프 | 큰 세계의 국소 변경에 유망하지만 GPS·탐색·시야 표현을 함께 재설계해야 한다. 별도 실험으로 남긴다. |
| 참여자의 현재 커서에 대한 순서 있는 행동 | 선택. 서버가 현재 위치에서 주소를 계산하고, 브라우저는 같은 규칙으로 즉시 표시한다. 크기 변경은 커서와 임시 문맥을 보정한다. |

## 이번 구현

브라우저는 `input` 메시지로 상대 이동, 주소로 이동, Home, Enter, Backspace/Delete, 네이티브 편집 의도를 보낸다. 메시지에는 연결 내 순번이 있으며, `epoch`는 진단용이다. 보정된 커서에서 순서대로 실행하고 이미 처리한 순번을 다시 실행하지 않는다. 거부된 시도도 순번을 소비하므로 429 뒤 입력 순서에 구멍이 생기지 않는다.

네이티브 편집은 `context`, UTF-16 `start/end`, 교체 문자열, 선택 경계만 전한다. 조합 초안과 매번의 전체 입력 문자열은 보내지 않는다. 브라우저 표준 이벤트와 OS가 조합을 계속 맡는다. 서버의 작은 임시 문맥은 해당 참여자가 확정한 범위와 세계 칸의 대응만 기억하며, 문서나 영구 셀 식별자가 아니다. 새 입력은 현재 커서에서, 재변환은 보정된 기존 입력 범위에서 실행한다. 사라진 칸은 치환 삭제 목록에서 제외한다. 없어진 글을 그대로 복구한다는 보장은 없다.

크기 변경 때 커서와 줄 시작 열을 보정한다. 삭제된 좌표는 해당 변환에서 다음으로 살아남는 칸으로 옮긴다. 끊어진 Backspace 경로는 버리고 보정된 커서에서 이어지는 경로만 남긴다. CJK 뒤쪽 칸이 head 옆으로 복구됐다면 실제 복구 위치를 사용한다. 사라진 옛 tail 주소를 계속 지우려다 403이 발생하는 결함을 재현해 수정했다.

재배치 snapshot에는 개인의 확정 입력 문맥과 마지막 처리 순번을 넣는다. 브라우저는 아직 처리되지 않은 행동을 새 커서에서 **화면 예측에만 다시 적용**한다. 네트워크로 재전송하지 않는다. 조합 DOM을 유지하며, 커서 좌표 변화만큼 카메라를 함께 옮겨 화면 속 커서가 튀지 않게 한다. 원거리 평행 이동이면 글자·망점의 실제 픽셀도 그대로다. 가까운 변경 경로에서는 글이 움직이거나 사라질 수 있다. 드래그·휠·관성의 남은 픽셀 이동량은 보정된 커서에서 계속 적용한다.

보통 ACK는 순번과 커서만 보낸다. 다른 사용자의 덮어쓰기 때문에 Backspace 대상 폭 등이 달라져 서버 커서와 예측이 다르면, 최신 snapshot으로 보정한다. 오래된 ACK를 현재 커서에 바로 대입해 더 최근 입력을 되감지 않는다.

HTTP/MCP turn은 매 단계의 현재 세계와 보정된 커서를 사용한다. 기존 10자/초 타이핑, 이동 속도, 시야·쓰기 예산, 429, 중복 방지, 취소·부분 완료 계약을 유지한다. 확장·축소만으로 남은 행동을 중단하지 않는다. HTTP 관측은 다음 응답에서 새 좌표의 reset을 받는다.

## 경계와 비용

- 브라우저 네이티브 문맥은 확정 문자열이 256 UTF-16 단위를 넘으면 조합 종료 후 선택 위치 주변의 최근 128~256 단위를 남긴다. Grapheme 경계와 선택 범위를 온전히 보존하므로 긴 묶음은 이보다 클 수 있다. 마지막 음절은 남겨 즉시 재변환할 수 있다. 서버는 최대 4,352 UTF-16 단위·512개 grapheme 항목, 브라우저 경로는 512단계로 제한한다. 세계 크기에 비례해 입력 문맥을 늘리지 않는다.
- 한 번의 입력 64 grapheme·4,096 UTF-16, 치환 주소 128개와 기존 참여자·네트워크 예산은 유지한다. 임의의 세계 좌표 목록을 새 프로토콜로 받지 않는다.
- 영구 저장되는 글자별 ID·타임스탬프·변환 이력을 추가하지 않았다. 해당 참여자의 입력 문맥은 연결 메모리에만 있다.
- 이미 열려 있는 이전 클라이언트의 절대 좌표 프로토콜에는 epoch 검사를 유지한다. 한 연결에서 좌표 방식과 새 커서 방식을 혼합하지 못하게 했다. 새 브라우저 코드를 받으려면 새로고침해야 한다.
- 실제 연결이 끊기면 새 참여 세션이다. 위치는 복구하지만 작성 기준 열·Backspace 경로는 새로 시작한다. 이전 구현의 로컬 재접속 경로 복원은 이번 서버 문맥 모델에서 유지하지 않았다. 재배치와 연결 종료를 구분하며, 미확정 입력은 재접속 때 자동 재전송하지 않는다.
- 전역 밀도 제어, 전체 셀 재저장, 세계 최대 크기, 단일 writer는 그대로다. 이번 변경은 선형 scale-out이나 무중단 remesh를 구현한 것이 아니다.

## 측정과 다음 실험

실시간 자동 제어와 실제 Chromium 두 창으로 한글·중국어 입력 60건을 수행했다. 자동 크기 변경 14회 중 60/60건 커밋, 페이지·프로토콜 오류 0건이었다. 표본 최대 밀도 12.67%, 마지막 10.39%였다. 일반 입력 메시지 72개(탐색·Enter 포함)는 평균 192.46바이트, 최대 211바이트였다. 개인 문맥이 포함된 snapshot 필드 30개는 평균 2,017.8바이트, 최대 2,937바이트였다. 압축 전 애플리케이션 JSON이며 Railway 청구 egress나 서버 수용 인원 측정이 아니다. 이전 실험과 seed·타이밍이 달라 직접 성능 우열을 주장하지 않는다.

`input.cursor_actions`, `input.after_resize`, `input.plan_ms`, `input.context_entries`, `input.snapshot_bytes`를 기존 집계에 추가했다. 마지막 지표는 개인 `input.state`의 JSON 크기다. 위 실험의 snapshot 필드 크기는 순번과 state를 함께 센다. 본문·좌표·입력 문맥 자체를 운영 측정 로그에 저장하지 않는다.

다음 실험은 실제 모바일 OS 키보드와 100~500ms 네트워크 지연에서 국소적인 강제 확장·축소를 반복하며, 커서 보정 거리·화면 이동량·입력 지연·문맥 전송량을 함께 비교하는 것이다. 현재 검증은 Chromium/CDP와 명시적인 표준 이벤트 순서 사례이며 실제 iOS·Android·Safari의 IME 검증을 대신하지 않는다.
