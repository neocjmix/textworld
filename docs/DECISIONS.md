# Decision Log

## 2026-11-02 · 실험 001: 두 사용자가 사는 글자 공간

제품 헌법은 그대로 유지한다. 아래 선택은 실험으로 검증할 수 있는 구현 선택이며 헌법에 새로운 조건을 추가하지 않는다. 좌표·확장·GPS 모델은 영구 설계로 확정하지 않았다.

### D001 — 공간은 문자열 문서가 아니라 희소 셀 집합

**맥락:** 입력이 이웃을 밀면 헌법의 덮어쓰기 불변식이 깨진다. 한 번에 두 사용자가 동일 셀을 수정할 수 있어야 한다.

**대안:** dense 배열, sparse 정수 좌표, 정규화된 연속 좌표, immutable 행/열 ID, 적응적 지리 atlas. 문서의 문자 삽입·OT·sequence CRDT는 본 문제의 공간 정체성을 해결하지 않으므로 기본 자료구조로 택하지 않았다.

**선택:** 메모리 Map과 SQLite `(x,y)` 키의 희소 셀. Unicode NFC 후 grapheme 한 개를 셀에 저장한다. 긴 grapheme은 셀 폭 안으로 그린다. 행의 끝에서는 같은 행 첫 칸으로 연결한다. 다중 행 붙여넣기의 newline은 입력 시작 열로 돌아간다. 빈 문자열은 삭제, 공백은 기록된 글자다.

**증거:** overwrite/delete 이웃 불변, 토러스 경계, 한글·결합문자·가족 이모지 테스트. 브라우저와 서버가 `shared/world.js`의 동일한 writePlan을 사용한다. 초기 프런트엔드의 독립 좌표 계산은 탭 하나를 한 칸으로 계산해 4칸으로 해석하는 서버와 달랐다. 중복 계산을 제거했다.

**가역성/다음:** 셀 identity를 row/column ID로 바꾸는 후속 비교가 가능하다. Canvas와 전송 프로토콜을 엔진 저장소에서 분리했다. wide 문자·emoji 렌더링의 가독성은 실제 기기에서 추가 비교한다.

### D002 — 동시 쓰기는 서버 수신 순서, 저장 완료 후 방송

**대안:** client-clock LWW, 셀별 multi-value register, 일반 입력 CAS, 지역 lease, 단일 서버 순서. client clock은 시계 편차, multi-value는 표시 중재, lease는 경계 권위 이전을 먼저 해결해야 한다.

**선택:** Node 단일 writer가 증가하는 seq로 직렬화하고 SQLite WAL 트랜잭션을 커밋한 뒤 방송한다. 같은 세션/작업 ID의 재전송은 중복 실행하지 않는다. 일반 입력은 다른 글을 자유롭게 덮어쓰고, scavenger만 CAS를 사용한다. 한 작업 안에서 같은 셀을 여러 번 쓰면 마지막 글자를 남긴다.

**증거:** 독립 WebSocket 클라이언트의 동시 경쟁 입력에서 동일한 seq/최종 셀로 수렴했다. 재시작 복구 및 같은 작업 재전송을 검증했다.

**실험 단축:** 단일 서버·동기 SQLite·전체 방송. 서버 지연 편향, 단일 장애점, 전체 세계 크기에 비례하는 비용이 있다. 멀티리전이나 오프라인 협업을 해결했다고 주장하지 않는다. 재접속은 새 session이므로 미확정 입력을 재생하지 않고 현재 snapshot을 받는다. 이동 위치는 새 연결에 복원한다.

### D003 — 크기 변경은 epoch를 가진 토러스, 안전하지 않은 축소는 보류

**대안/증거:** [EXPERIMENTS.md](EXPERIMENTS.md)의 실행 반례에서 정규화 remap과 단순 modulo 축소는 16문자 중 4문자를 충돌시켰다. 빈 strip 변환은 해당 fixture의 충돌·인접성 손실을 피했다. 이것이 모든 분포에서 성립하는 것은 아니다.

**선택:** 10초마다 `max(점유 셀 수, 접속자 수×96)/면적`을 평가한다. 25% 초과면 가로·세로를 두 배, 4% 미만이면 절반으로 제안하며 30초 cooldown을 둔다. 제거할 band에 문자나 커서가 있으면 축소를 보류한다. 실제 변경은 원자적 meta 갱신과 전체 snapshot으로 전파하고 이전 epoch 입력은 명시적으로 거절한다. 새 epoch snapshot은 동일 연결에 반복 전송하지 않아 오래된 입력 다발이 새 입력 커서를 되돌리지 않는다.

**실험 단축:** 임계값과 32×16~1024×512 범위는 운영 정책이 아니라 실험 파라미터다. 비어 있는 끝부분을 추가하므로 확장 시 옛 경계를 가로지른 문장이 떨어질 수 있다. 중앙 공동 출발점 자체가 절반 축소의 경계에 남아 축소를 보류시킬 수도 있다. 보존을 위해 조용히 문자를 재배치/소실시키지 않는다.

**다음:** immutable row/column ID + 빈 strip 삽입/삭제를 동일한 경계 문장·사용자 배치로 실험한다. 전역 면적 확장만으로 지역 커서 밀집이 줄어드는지도 측정한다.

### D004 — GPS는 클라이언트에서 등적 원통 투영

**대안:** equirectangular, Mercator, sin(latitude) 등적 투영, 고정 atlas anchor, 동적 geographic cell 분할. sphere와 torus의 위상 차이는 어떤 투영도 제거할 수 없다.

**선택:** 경도는 주기적으로, 위도는 sin으로 현재 extent에 양자화한다. 서버는 셀만 받고 정확한 위도·경도는 받지 않는다. 최초 자동 요청이 거절/실패하면 중앙 공동 출발점, 공유 링크는 명시된 장소로 들어간다. 최초 GPS 응답이 늦는 동안 사용자가 이동했으면 위치를 덮어쓰지 않는다. GPS 버튼은 캐시하지 않은 현재 위치를 요청한다.

**증거/수정:** ±180°/극점/유효 범위 검사, 권한 허용·거절 브라우저 흐름을 검증했다. GPS 버튼에서 maximumAge=60초를 재사용하자 위치 변경 후에도 캐시된 이전 위치로 돌아갔다. 명시적 GPS 복귀는 maximumAge=0으로 수정했고 새 위치 이동이 통과했다.

**한계:** 양자화된 셀도 대략적 지역을 드러낸다. resize 시 같은 GPS의 착지점이 바뀐다. 영구적 장소 주소를 보장하지 않는다. 다음 실험은 고정 atlas anchor의 재방문 거리와 새 공간 도달 범위를 비교한다.

### D005 — Canvas viewport와 실제 textarea 입력

초기 실험의 기록이다. 화면 구성과 커서·pan 관계는 아래 D008로 대체한다.

**대안:** 전체 DOM grid, Canvas, GPU 타일. 초기 작은 세계에서는 Canvas가 수천 DOM 셀 없이 같은 칸 크기와 터치 탐색을 제공한다. IME를 직접 구현하지 않고 native textarea composition을 이용한다.

**선택:** 한국어 UI, canvas 렌더링, 키보드/터치 입력, 이동·pan·bounded zoom. pan은 커서를 화면 안의 가장 가까운 칸으로 옮긴다. 이동 전송은 40ms로 합치고 동일 셀을 중복 전송하지 않는다. 입력/삭제는 명시적 셀 주소를 전송한다. 서버 확인 전 글자를 확정 표시하지 않고 전송 상태를 표시한다.

**증거/수정:** 실제 Chromium에서 두 context의 상호 입력·presence, native IME 조합 완료 1회 기록, 토러스 이동, 줌 한계, mobile touch/짧은 viewport를 검증했다. 동일 페이지 hash 변경도 위치 이동으로 처리하도록 고쳤다. 빠른 pan이 서버 제한을 소모하는 문제와 reconnect 순간 위치 초기화도 수정했다. 조합 중 위치/epoch가 바뀌면 이전 조합 완료를 취소했고(주소가 보존된 자동 크기 변경의 예외는 D013에서 보완), 빈 textarea의 mobile beforeinput 삭제 경로를 처리한다.

**한계:** CDP IME와 모바일 에뮬레이션이 실제 iOS/Android 한국어 키보드 검증을 대신하지 않는다. 화면 읽기 도구에 전체 격자를 제공하는 접근성은 후속 작업이다. 문자 선택/범위 편집은 구현하지 않았다.

### D006 — 정리 정책과 코어 증거를 분리

**선택:** 셀 버전, 작성 session, 갱신 시각, 작업 묶음, 변경 history를 저장한다. 관리 API는 현재 셀과 묶음 생존/원래 크기를 제공한다. 별도 scavenger 프로그램이 나이 기준으로 후보를 고르고 epoch+version 조건부 삭제를 요청한다. 토큰이 없으면 관리 API를 제공하지 않는다.

**대안:** 엔진 내부 TTL, 무조건 DELETE, 독립 증거 기반 정리. 내부 TTL은 정책 결합, 무조건 삭제는 새 글 삭제 위험 때문에 선택하지 않았다.

**증거:** evidence 이후 덮어쓴 글은 오래된 정리 요청으로 지워지지 않는다. 삭제는 일반 셀 패치로 즉시 전파된다. 별도 프로그램의 수명 기본값 24시간은 실험값이며 제품 약속이 아니다.

**실험 단축/위험:** history와 작업 중복 방지 레코드는 아직 무기한 보관한다. 표시상의 ephemeral과 개인정보의 삭제 보장은 다르다. 기록 retention/compaction, 정리 작업 스케줄링과 공개 서비스 abuse 대응은 운영 이전에 설계해야 한다. 미래 private world의 정책을 이 public 엔진에 섞지 않았고 아직 private world는 구현하지 않았다.

### D007 — 첫 공개 배포는 Railway 단일 서비스와 영구 볼륨

2026-11-02 사용자의 Railway 배포 요청에 따라 `Textworld/production`에 GitHub main을 배포 소스로 연결했다. 문서 push의 자동 배포 시작은 확인하지 못해 최신 소스 배포를 명시적으로 시작하며, 자동 배포는 후속 확인 대상으로 남긴다. Node 24, Railpack, `/health`, `us-west2` replica 1, `/data` 1024 MB 영구 볼륨을 사용한다. SQLite 본체·WAL·SHM이 모두 볼륨에 놓이도록 `TEXTWORLD_DB=/data/world.sqlite`를 설정했다. 임시 파일시스템에 DB를 두는 방식은 재배포 손실 때문에 배제했다. 별도 Postgres로 전환하는 대신 이미 검증한 단일 writer를 유지한다. 운영 설정과 공개 URL은 [DEPLOYMENT.md](DEPLOYMENT.md)에 기록한다. 수평 복제·자동 history 정리·정기 백업은 이 배포에 포함하지 않는다. 이 선택은 향후 저장소를 바꾸거나 서비스를 이전할 수 있는 구현 선택이다.


### D008 — 지도 전체 화면, 중심 커서, 지도 위 네이티브 입력

2026-11-02 사용자가 “C 월드맵 전체화면”, “xy 스크롤 자체가 커서 이동”, “화면 중심에 항상 커서”, “E 입력 패널 제거”, “지도앱”을 명시했다. 이를 현재 UI의 기준으로 적용한다. 제품 헌법의 단일 셀 커서·viewport 결합을 더 구체적인 상호작용으로 구현하며, `PRODUCT_CONSTITUTION.md`는 변경하지 않는다.

**선택:** 월드맵이 브라우저의 보이는 콘텐츠 영역 전체를 채운다. 내 커서는 중심 한 칸에 고정하고, 가로·세로 탐색과 방향키는 그 중심이 가리키는 세계 좌표를 변경한다. 글자 입력으로 다음 셀로 진행할 때도 카메라가 따라가므로 화면상 커서 위치는 변하지 않는다. 지도 탭은 현재 중심에서 입력을 시작하며 탭 위치로 커서를 이동시키지 않는다. 화면 정보바·별도 입력 패널·푸터를 제거하고 연결 상태·접속자 수·좌표·GPS·공유·줌·도움말만 지도 위의 작은 오버레이로 남긴다.

**탐색 대안:** (1) 자유로운 fractional 카메라를 쓰고 가까운 셀을 선택하면 드래그는 부드럽지만 선택 셀 중심이 화면 중심을 벗어난다. (2) 중심 reticle만 고정하면 셀 경계와 커서 외곽이 어긋나 어떤 칸에 쓰는지 모호해진다. (3) 카메라를 셀 단위로 이동하고 작은 입력량을 누적하면 한 셀의 중심과 화면 중심을 항상 일치시킬 수 있다. 이번 구현은 3을 선택한다. 셀 단위로 움직이는 촉감은 실험 선택이며, 작은 스크롤을 버리지 않도록 잔여 이동량을 누적한다. 후속 실험은 입력 위치의 명확성을 유지하면서 탐색 촉감을 개선하는 것이다.

**입력 대안:** 전역 keydown만으로 문자를 만들면 OS의 한글 조합·모바일 키보드·붙여넣기 경로를 온전히 활용할 수 없다. 기존처럼 별도 textarea 패널을 두는 방식은 사용자가 명시적으로 제거했다. 따라서 실제 native textarea를 중심 셀에 배치해 포커스·IME 입력을 받되, 별도 시각적 입력창을 만들지 않는다. 조합 중 글자는 중심 셀에서 로컬 미리보기로 그리고, 조합 완료 후에만 공유 세계에 확정한다. 실제 위치가 바뀌거나 주소 보존이 확인되지 않은 epoch 변경으로 취소된 조합을 다른 셀에 기록하지 않는 규칙은 유지한다. 주소가 보존된 자동 크기 변경의 문맥 유지 조건은 D013에 따른다.

**모바일:** 키보드가 뜨면 visualViewport를 기준으로 앱 영역을 맞춰 키보드를 제외한 지도 중심에 커서와 입력 기준점을 유지한다. GPS·공유·줌·도움말은 네이티브 키보드 입력을 가로막지 않는 지도 오버레이로 유지한다. OS 키보드와 한글 후보창은 브라우저·운영체제가 제공한다.

**검증 범위:** 이번 변경은 중심 셀과 viewport 중심의 일치, 가로·세로 탐색에 따른 presence, 직접 입력 후 카메라 추종, 줌·resize·재접속, 한글 조합의 단일 커밋과 취소를 브라우저 테스트에서 확인해야 한다. 실제 실행 결과는 검증 기록에 별도로 남긴다. 모바일 에뮬레이션과 CDP IME를 실제 iOS/Android 키보드 검증으로 간주하지 않는다.


### D009 — 입력 이벤트가 아니라 작성 의도를 유지

2026-11-02 사용자가 Enter 동작을 제품 목적과 기대에 비추어 다시 판단하라고 요청했다. 현재 열 유지, 세계 0열 복귀, 주변 글 추론, 전송/입력 종료, 로컬 작성 기준 열 복귀를 비교했다. [INPUT_DESIGN.md](INPUT_DESIGN.md)에 비교와 기존 실행 반례를 기록한다. `ABC` 뒤 Enter가 계단 모양을 만들고, 동일한 `ABC\nD`가 이벤트를 나눠 받으면 다른 좌표에 배치되는 실패 때문에 로컬 작성 기준 모델을 선택했다. 기존 D001/D005에 기록한 현재 열 다음 행 동작은 이 결정으로 대체한다.

**선택:** 첫 글쓰기의 기준 열을 유지해 Enter·Shift+Enter·모바일 줄바꿈·붙여넣기를 같은 공간 계획으로 처리한다. 원래 쓰던 행의 좌표를 이동시키거나 글자를 밀지 않는다. 줄바꿈만 있으면 presence만 이동하고 DB 쓰기는 만들지 않는다. 클라이언트와 서버가 선택적 `lineStartX`를 공유하고, 이를 생략한 기존 클라이언트 요청은 기존 paste 시작 열로 해석한다.

**탐색과 교정 구분:** 지도 pan·GPS·좌표 링크는 새 장소 선택이므로 기준을 초기화한다. 반면 활성 작성 중 방향키로 오타를 고친 것까지 새 문장의 시작으로 취급하면 같은 판단 오류가 반복된다. 방향키는 작성 전에는 예상 기준을 옮기고, 작성 중에는 기준을 보존하되 과거 역추적 경로를 비운다. Home은 현재 행의 기준 열로 이동한다. 줌·키보드 표시·포커스와 확정된 동일 epoch 재접속은 기준을 보존한다. 주소 보존 조건을 충족한 자동 크기 변경도 D013에 따라 문맥과 기준을 유지한다. 그 밖의 epoch 변경·일반 재동기화·오류 복구·불확실한 입력 복구는 초기화한다.

**Backspace:** 공통 planner가 반환하는 실제 문자/return 전이를 로컬에서 최근 4096개까지 기억한다. Backspace는 문자 전이를 한 칸 지우며 거슬러 가고, return 전이는 어느 셀도 지우지 않고 이전 줄 끝으로 돌아간다. 명시적 커서 이동 뒤에는 세계에서 줄 끝을 추측하지 않고 왼쪽 칸만 삭제한다. 이는 undo나 소유 문단이 아니며 타인의 후속 글을 이전 버전으로 되돌리지 않는다. 경로는 서버에 저장하지 않는다.

**다른 native 입력 의도:** keydown·beforeinput·input의 줄바꿈/삭제를 같은 명령으로 연결했다. IME 확정 Enter를 앱 줄바꿈으로 중복 처리하지 않는다. 범위 선택·복사·잘라내기, 단어/행 삭제, undo/redo, 문맥 없는 자동 치환을 새 글 삽입으로 오인하지 않고 명시적 미지원·무변경으로 처리한다. 이 제한은 지도 입력 수신기에만 적용하며 도움말·브라우저의 선택/복사를 막지 않는다. Tab은 접근성 포커스 이동, 붙여넣은 tab은 공백4칸으로 둔다. 전역 문자열이 없으므로 End가 이동할 줄 끝을 추론하지 않는다.

**한계와 다음 실험:** 이 기준 수명은 실제 사용자 연구로 확정된 사실이 아니다. 시·ASCII 배치·기존 글 오타 수정 과제를 수행하며 기준을 예측하는지 관찰한다. iOS/Android의 IME 확정과 자동 치환 이벤트는 실제 기기 검증이 필요하다. 제품 헌법은 변경하지 않았다.

### D010 — 한글 조합은 OS 입력 문맥을 보존하고 최근 공간 경로에 적용

2026-11-02 사용자가 한글 입력이 낱자로 분리된다고 보고했다. 이미 시작된 한 음절의 조합 완료만 검사한 기존 테스트로는 이 문제를 배제할 수 없었다. 실제 Chromium CDP에서 첫 `ㅎ` 입력 후 OS가 이전 범위를 `하 → 한`으로 조합 교체하면 `ㅎ한`이 남는 반례를 재현했다. 매 input·compositionend 직후 textarea를 비우는 구현이 OS의 교체 범위를 없앴다.

**대안과 선택:** 매 이벤트 뒤 입력창 초기화는 문맥을 끊으므로 기각했다. 앱 내부 한글 조합기 구현은 OS 키보드·후보 선택·다른 언어를 다시 구현하게 되므로 기각했다. textarea 전체를 문서로 동기화하면 셀 삽입·reflow를 유도하므로 기각했다. 네이티브 버퍼를 보존하고 확정 문맥과 새 값의 grapheme 단위 차이만 공간 입력으로 변환한다. 문자 조합은 계속 OS가 담당한다.

**교체 범위:** 현재 커서에서 로컬 작성 경로로 확인할 수 있는 끝부분의 최대 32개 문자만 교체할 수 있다. 명시적인 탐색·편집 명령·일반 재동기화는 네이티브 문맥 경계를 새로 잡는다. 주소 보존 조건을 모두 충족한 자동 크기 변경에서는 D013에 따라 문맥과 작성 경로를 유지한다. 취소된 조합의 늦은 완료와 확정 뒤 companion input은 새 글로 재삽입하지 않는다. 일반 문서형 범위 편집·자동 교정·undo를 지원한다는 뜻은 아니다. 최근 글을 다른 사람이 덮어썼다면 일반 공개 공간의 덮어쓰기 규칙을 적용하며 소유권이나 과거 버전 복원을 만들지 않는다.

**실험 경계:** 32개 한도는 구현 선택이다. Chromium의 native 범위 교체와 이벤트 순서 검사는 실제 iOS·Android 키보드 검증을 대신하지 않는다. 기기별 연속 음절·후보 확정·삭제를 다음 입력 실험으로 남긴다. 실제 실행 결과는 [VERIFICATION.md](VERIFICATION.md)에 기록한다.

### D011 — CJK 표시 폭은 기본 칸의 1배 또는 2배

사용자는 CJK 고정폭 글꼴의 간격 규칙을 요청하되 그 글꼴 자체를 쓰지는 말라고 했다. 바이트 수는 인코딩마다 달라 표시 기준에서 제외한다. 폰트의 실제 픽셀 폭을 주소로 사용하면 기기별 fallback에 따라 세계 배치가 바뀐다. 저장은 한 칸으로 둔 채 그림만 늘리는 방식은 이웃 글과 겹치고 입력·삭제 위치가 어긋난다.

**선택:** Unicode 17 East Asian Width W/F와 emoji 표시 묶음은 2칸, 반각·중립·ambiguous 문자는 1칸으로 계산한다. 결합 부호는 기저 문자에 폭을 더하지 않는다. 공통 폭 함수를 서버·클라이언트가 사용한다. 실제 글꼴은 Arial·플랫폼 한글 sans-serif를 유지하고 기본 칸은 12×30px로 둔다. D001의 grapheme 하나를 항상 한 칸에 그리는 선택은 새 입력에서 이 결정으로 대체한다.

**공간 표현:** 두 칸 문자는 시작 셀 `{text,width:2}`와 연속 셀 `{text:'',width:0,leadX}`의 쌍이다. 두 셀은 점유·저장·전파되며 어느 절반을 삭제·덮어써도 기존 쌍을 원자적으로 정리한다. 다른 글을 밀지는 않는다. 토러스 경계를 넘는 쌍, 반복 주소 paste, scavenger의 버전 조건도 같은 쌍 규칙을 따른다. 커서는 여전히 기본 칸 하나를 가리킨다.

**데이터와 실험 제한:** 기존 글의 폭을 일괄 확장하면 이웃을 지우거나 밀 수 있으므로 이전 기록은 주소·내용·버전을 유지하고 `width:1`로 읽는다. 새 입력부터 새 폭을 적용한다. SQLite에는 폭 메타데이터를 추가하며 백업·복구 조건은 [DEPLOYMENT.md](DEPLOYMENT.md)에 기록한다. 새 write/erase는 `layout:2`를 요구하고 구클라이언트에는 새로고침을 안내한다. 좌우 경계를 가로지르는 두 칸 문자가 있으면 너비 변경을 보류한다. 이 보류는 쌍의 인접성을 보존하는 현재 단축 선택이며 영구 크기 적응 알고리즘은 아니다.

**다음:** 혼합 한글·영문·emoji의 읽기와 수정 과제에서 표시 폭을 검증하고, 좌표·인접성을 함께 보존하는 resize 모델을 다시 비교한다. Unicode 버전 갱신은 공유 세계 배치를 바꿀 수 있으므로 데이터 파일과 버전을 명시적으로 관리한다.

### D012 — 드래그 관성은 추가하고 휠의 OS 관성은 중복하지 않음

**대안:** 즉시 정지는 기존의 딱딱한 탐색 촉감을 남긴다. 모든 이동에 동일한 fling을 더하면 OS가 이미 감속하는 트랙패드 wheel의 이동을 중복 증폭한다. 완전한 fractional 카메라로 바꾸면 셀 중심과 화면 중심의 일치를 다시 설계해야 한다.

**선택:** 마우스·터치 드래그를 놓을 때 최근 속도에 지수 감속을 적용한다. wheel은 전달받은 이동량만 짧게 평활화하고 총량을 유지한다. 관성도 기존 픽셀 누적기와 기본 칸 주소 이동을 사용하므로 커서 중심 불변식과 원격 presence 경로를 공유한다. 타이핑·IME 시작·새 제스처·줌·GPS·좌표 링크·도움말·연결 중단·resize·탭 숨김에서는 남은 관성을 버린다. 핀치의 이전 속도를 남은 손가락에 재사용하지 않는다. reduced-motion에서는 fling을 끄고 wheel을 즉시 전달한다.

**실험값과 실패:** 속도 추정 최근 80ms, 감속 시정수 220ms, 최대 꼬리 1400ms, wheel 평활화 45ms를 초기값으로 둔다. 실제 Chromium 검증에서 RAF timestamp가 같은 프레임의 pointerup 시각보다 이를 수 있어 관성이 즉시 취소되는 실패를 발견했다. 하나의 단조시계로 시간을 읽도록 바꾸었다. 프레임률 독립 이동과 긴 중단 뒤 점프 방지는 유지한다. 셀 단위 이동의 촉감과 감속 수치는 실기기에서 후속 조정한다. 이 선택도 제품 헌법을 변경하지 않는다.


### D013 — epoch 변화와 작성 주소의 변화를 구분

**실제 배포에서 발견한 실패:** D010의 네이티브 버퍼 보존 수정 후 첫 Railway 공개 검증에서도 `ㅎ`를 `한`으로 고치는 데 실패했다. 재시도는 통과했고 그 사이 세계 epoch 변경을 확인했다. 이를 단서로 `ㅎ` 확정과 다음 조합 사이에 주소가 그대로인 density resize를 넣어 `ㅎ한` 중복을 로컬에서 재현했다. snapshot 수신 코드가 버퍼를 비우는 별도 원인을 확인했다. 입력 모듈이 문맥을 유지하는 것만으로는 충분하지 않았고, 세계 갱신과 조합이 겹치는 경우를 기존 검사에서 놓쳤다.

**재판단:** 모든 epoch 변경에서 문맥을 버리면 위치가 그대로인 자동 확장도 사용자의 한글 입력을 끊는다. 모든 snapshot에서 문맥을 유지하면 실제 위치 변경·오류 복구·미확정 쓰기를 과거 입력 범위와 잘못 연결한다. 따라서 epoch 숫자만으로 판단하지 않고 서버의 주소 보존 보장과 클라이언트의 현재 작성 상태를 함께 확인한다.

**선택:** 현재 서버 resize는 점유된 주소를 옮기지 않고 빈 가장자리 영역만 추가·제거한다. 이 변경의 성공 결과에만 `preservesAddresses:true`를 보낸다. 클라이언트는 살아 있는 연결의 `density-resize` snapshot이고, 해당 표시가 있으며, pending 쓰기가 없고, 본인 session ID와 커서 좌표가 같고, 작성 기준 열 및 역추적 경로의 모든 좌표가 새 범위에 들어가며 각 문자 진행·줄바꿈의 인접성도 유지될 때만 네이티브 버퍼·조합 미리보기·작성 기준·경로를 보존한다. 최종 조합 확정은 새 세계·epoch를 사용한다. 예를 들어 128열 세계에서 126→0으로 진행한 기록은 256열로 늘어나면 더 이상 같은 인접 관계가 아니므로 보존 대상에서 제외한다.

**계속 초기화하는 경우:** 일반 sync·오류 복구·실제 위치 이동·결과가 불확실한 쓰기·주소 보존을 확인할 수 없는 epoch 변경에서는 이전 문맥을 취소한다. 재접속 때의 기존 작성 기준 보존 규칙과, 연결 중 주소 보존 resize에서 네이티브 조합을 보존하는 규칙은 구분한다. 미래의 remap resize가 현재의 주소 보존 표시를 그대로 재사용해서는 안 된다.

**검증과 한계:** 첫 자모 확정 뒤 자동 resize, 조합 진행 중 자동 resize, 일반 sync·불확실한 쓰기의 취소를 각각 검사해야 한다. 실제 실행 결과와 공개 재배포 검증은 [VERIFICATION.md](VERIFICATION.md), [DEPLOYMENT.md](DEPLOYMENT.md)에 기록한다. 주소 보존은 미래의 모든 토폴로지 변환에 대한 약속이 아니며, 제품 헌법은 변경하지 않았다.
