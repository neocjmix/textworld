# Decision Log

## 2026-11-02 · 실험 001: 두 사용자가 사는 글자 공간

제품 헌법은 그대로 유지한다. 아래 선택은 실험으로 검증할 수 있는 구현 선택이며 헌법에 새로운 조건을 추가하지 않는다. 좌표·확장·GPS 모델은 영구 설계로 확정하지 않았다.

### D001 — 공간은 문자열 문서가 아니라 희소 셀 집합

**맥락:** 입력이 이웃을 밀면 헌법의 덮어쓰기 불변식이 깨진다. 한 번에 두 사용자가 동일 셀을 수정할 수 있어야 한다.

**대안:** dense 배열, sparse 정수 좌표, 정규화된 연속 좌표, immutable 행/열 ID, 적응적 지리 atlas. 문서의 문자 삽입·OT·sequence CRDT는 본 문제의 공간 정체성을 해결하지 않으므로 기본 자료구조로 택하지 않았다.

**선택:** 메모리 Map과 SQLite `(x,y)` 키의 희소 셀. Unicode NFC 후 grapheme 한 개를 셀에 저장한다. 긴 grapheme은 셀 폭 안으로 그린다. 행의 끝에서는 같은 행 첫 칸으로 연결한다. 다중 행 붙여넣기의 newline은 입력 시작 열로 돌아간다. 빈 문자열은 삭제, 공백은 기록된 글자다.

**증거:** overwrite/delete 이웃 불변, 토러스 경계, 한글·결합문자·가족 이모지 테스트. 브라우저와 서버가 `shared/world.js`의 동일한 writePlan을 사용한다. 초기 프런트엔드의 독립 좌표 계산은 탭 하나를 한 칸으로 계산해 4칸으로 해석하는 서버와 달랐다. 중복 계산을 제거했다.

**가역성/다음:** 셀 identity를 row/column ID로 바꾸는 후속 비교가 가능하다. Canvas와 전송 프로토콜을 엔진 저장소에서 분리했다. wide 문자·emoji 렌더링의 가독성은 실제 기기에서 추가 비교한다.

### D002 — 동시 쓰기는 서버 수신 순서, 저장 완료 후 방송

**대안:** client-clock LWW, 셀별 multi-value register, 일반 입력 CAS, 지역 lease, 단일 서버 순서. client clock은 시계 편차, multi-value는 표시 중재, lease는 경계 권위 이전을 먼저 해결해야 한다.

**선택:** Node 단일 writer가 증가하는 seq로 직렬화하고 SQLite WAL 트랜잭션을 커밋한 뒤 방송한다. 같은 세션/작업 ID의 재전송은 중복 실행하지 않는다. 일반 입력은 다른 글을 자유롭게 덮어쓰고, scavenger만 CAS를 사용한다. 한 작업 안에서 같은 셀을 여러 번 쓰면 마지막 글자를 남긴다.

**증거:** 독립 WebSocket 클라이언트의 동시 경쟁 입력에서 동일한 seq/최종 셀로 수렴했다. 재시작 복구 및 같은 작업 재전송을 검증했다.

**실험 단축:** 단일 서버·동기 SQLite·전체 방송. 서버 지연 편향, 단일 장애점, 전체 세계 크기에 비례하는 비용이 있다. 멀티리전이나 오프라인 협업을 해결했다고 주장하지 않는다. 재접속은 새 session이므로 미확정 입력을 재생하지 않고 현재 snapshot을 받는다. 이동 위치는 새 연결에 복원한다.

### D003 — 크기 변경은 epoch를 가진 토러스, 안전하지 않은 축소는 보류

**후속 변경:** 보존 때문에 성장을 보류하던 선택은 사용자의 명시적 지시에 따라 D023으로 대체했다.

**대안/증거:** [EXPERIMENTS.md](EXPERIMENTS.md)의 실행 반례에서 정규화 remap과 단순 modulo 축소는 16문자 중 4문자를 충돌시켰다. 빈 strip 변환은 해당 fixture의 충돌·인접성 손실을 피했다. 이것이 모든 분포에서 성립하는 것은 아니다.

**선택:** 10초마다 `max(점유 셀 수, 접속자 수×96)/면적`을 평가한다. 25% 초과면 가로·세로를 두 배, 4% 미만이면 절반으로 제안하며 30초 cooldown을 둔다. 제거할 band에 문자나 커서가 있으면 축소를 보류한다. 실제 변경은 원자적 meta 갱신과 전체 snapshot으로 전파하고 이전 epoch 입력은 명시적으로 거절한다. 새 epoch snapshot은 동일 연결에 반복 전송하지 않아 오래된 입력 다발이 새 입력 커서를 되돌리지 않는다.

**실험 단축:** 임계값과 32×16~1024×512 범위는 운영 정책이 아니라 실험 파라미터다. 비어 있는 끝부분을 추가하므로 확장 시 옛 경계를 가로지른 문장이 떨어질 수 있다. 중앙 공동 출발점 자체가 절반 축소의 경계에 남아 축소를 보류시킬 수도 있다. 보존을 위해 조용히 문자를 재배치/소실시키지 않는다.

**다음:** immutable row/column ID + 빈 strip 삽입/삭제를 동일한 경계 문장·사용자 배치로 실험한다. 전역 면적 확장만으로 지역 커서 밀집이 줄어드는지도 측정한다.

### D004 — GPS는 클라이언트에서 등적 원통 투영

**대안:** equirectangular, Mercator, sin(latitude) 등적 투영, 고정 atlas anchor, 동적 geographic cell 분할. sphere와 torus의 위상 차이는 어떤 투영도 제거할 수 없다.

**선택:** 경도는 주기적으로, 위도는 sin으로 현재 extent에 양자화한다. 서버는 셀만 받고 정확한 위도·경도는 받지 않는다. 최초 자동 요청이 거절/실패하면 중앙 공동 출발점, 공유 링크는 명시된 장소로 들어간다. 최초 GPS 응답이 늦는 동안 사용자가 이동했으면 위치를 덮어쓰지 않는다. GPS 버튼은 캐시하지 않은 현재 위치를 요청한다.

**증거/수정:** ±180°/극점/유효 범위 검사, 권한 허용·거절 브라우저 흐름을 검증했다. GPS 버튼에서 maximumAge=60초를 재사용하자 위치 변경 후에도 캐시된 이전 위치로 돌아갔다. 명시적 GPS 복귀는 maximumAge=0으로 수정했고 새 위치 이동이 통과했다.

**한계:** 양자화된 셀도 대략적 지역을 드러낸다. resize 시 같은 GPS의 착지점이 바뀐다. 영구적 장소 주소를 보장하지 않는다. 다음 실험은 고정 atlas anchor의 재방문 거리와 새 공간 도달 범위를 비교한다.

### D005 — Canvas viewport와 실제 textarea 입력

초기 실험의 기록이다. 화면 구성과 커서·pan 관계는 아래 D008/D017로, textarea 입력 호스트는 D014로 대체한다. 서버 확인 전에는 글자를 보여주지 않던 표시는 D016의 즉시 로컬 반영으로 대체했다.

**대안:** 전체 DOM grid, Canvas, GPU 타일. 초기 작은 세계에서는 Canvas가 수천 DOM 셀 없이 같은 칸 크기와 터치 탐색을 제공한다. IME를 직접 구현하지 않고 native textarea composition을 이용한다.

**선택:** 한국어 UI, canvas 렌더링, 키보드/터치 입력, 이동·pan·bounded zoom. pan은 커서를 화면 안의 가장 가까운 칸으로 옮긴다. 이동 전송은 40ms로 합치고 동일 셀을 중복 전송하지 않는다. 입력/삭제는 명시적 셀 주소를 전송한다. 서버 확인 전 글자를 확정 표시하지 않고 전송 상태를 표시한다.

**증거/수정:** 실제 Chromium에서 두 context의 상호 입력·presence, native IME 조합 완료 1회 기록, 토러스 이동, 줌 한계, mobile touch/짧은 viewport를 검증했다. 동일 페이지 hash 변경도 위치 이동으로 처리하도록 고쳤다. 빠른 pan이 서버 제한을 소모하는 문제와 reconnect 순간 위치 초기화도 수정했다. 조합 중 위치/epoch가 바뀌면 이전 조합 완료를 취소했고(주소가 보존된 자동 크기 변경의 예외는 D013에서 보완), 빈 textarea의 mobile beforeinput 삭제 경로를 처리한다.

**한계:** CDP IME와 모바일 에뮬레이션이 실제 iOS/Android 한국어 키보드 검증을 대신하지 않는다. 화면 읽기 도구에 전체 격자를 제공하는 접근성은 후속 작업이다. 문자 선택/범위 편집은 구현하지 않았다.

### D006 — 정리 정책과 코어 증거를 분리

**선택:** 셀 버전, 작성 session, 갱신 시각, 작업 묶음, 변경 history를 저장한다. 관리 API는 현재 셀과 묶음 생존/원래 크기를 제공한다. 별도 scavenger 프로그램이 나이 기준으로 후보를 고르고 epoch+version 조건부 삭제를 요청한다. 토큰이 없으면 관리 API를 제공하지 않는다.

**대안:** 엔진 내부 TTL, 무조건 DELETE, 독립 증거 기반 정리. 내부 TTL은 정책 결합, 무조건 삭제는 새 글 삭제 위험 때문에 선택하지 않았다.

**증거:** evidence 이후 덮어쓴 글은 오래된 정리 요청으로 지워지지 않는다. 삭제는 일반 셀 패치로 즉시 전파된다. 별도 프로그램의 수명 기본값 24시간은 실험값이며 제품 약속이 아니다.

**실험 단축/위험:** history와 작업 중복 방지 레코드는 아직 무기한 보관한다. 표시상의 ephemeral과 개인정보의 삭제 보장은 다르다. 기록 retention/compaction, 정리 작업 스케줄링과 공개 서비스 abuse 대응은 운영 이전에 설계해야 한다. 미래 private world의 정책을 이 public 엔진에 섞지 않았고 아직 private world는 구현하지 않았다.

### D007 — 첫 공개 배포는 Railway 단일 서비스와 영구 볼륨

2026-11-02 사용자의 Railway 배포 요청에 따라 `Textworld/production`에 GitHub main을 배포 소스로 연결했다. 문서 push의 자동 배포 시작은 확인하지 못해 최신 소스 배포를 명시적으로 시작하며, 자동 배포는 후속 확인 대상으로 남긴다. Node 24, Railpack, `/health`, `us-west2` replica 1, `/data` 1024 MB 영구 볼륨을 사용한다. SQLite 본체·WAL·SHM이 모두 볼륨에 놓이도록 `TEXTWORLD_DB=/data/world.sqlite`를 설정했다. 임시 파일시스템에 DB를 두는 방식은 재배포 손실 때문에 배제했다. 별도 Postgres로 전환하는 대신 이미 검증한 단일 writer를 유지한다. 운영 설정과 공개 URL은 [DEPLOYMENT.md](DEPLOYMENT.md)에 기록한다. 수평 복제·자동 history 정리·정기 백업은 이 배포에 포함하지 않는다. 이 선택은 향후 저장소를 바꾸거나 서비스를 이전할 수 있는 구현 선택이다.


### D008 — 지도 전체 화면, 중심 커서, 지도 위 네이티브 입력

2026-11-02 사용자가 “C 월드맵 전체화면”, “xy 스크롤 자체가 커서 이동”, “화면 중심에 항상 커서”, “E 입력 패널 제거”, “지도앱”을 명시했다. 이를 현재 UI의 기준으로 적용한다. 제품 헌법의 단일 셀 커서·viewport 결합을 더 구체적인 상호작용으로 구현하며, `PRODUCT_CONSTITUTION.md`는 변경하지 않는다.

전체 화면·지도 이동으로 입력 위치를 고르는 원칙은 유지한다. 최초 textarea 구현은 D014로, 매 순간 중심을 고정하는 방식은 사용자의 후속 요청에 따라 D017의 이동 후 중심 재정착으로 대체했다.

**선택:** 월드맵이 브라우저의 보이는 콘텐츠 영역 전체를 채운다. 내 커서는 중심 한 칸에 고정하고, 가로·세로 탐색과 방향키는 그 중심이 가리키는 세계 좌표를 변경한다. 글자 입력으로 다음 셀로 진행할 때도 카메라가 따라가므로 화면상 커서 위치는 변하지 않는다. 지도 탭은 현재 중심에서 입력을 시작하며 탭 위치로 커서를 이동시키지 않는다. 화면 정보바·별도 입력 패널·푸터를 제거하고 연결 상태·접속자 수·좌표·GPS·공유·줌·도움말만 지도 위의 작은 오버레이로 남긴다.

**탐색 대안:** (1) 자유로운 fractional 카메라를 쓰고 가까운 셀을 선택하면 드래그는 부드럽지만 선택 셀 중심이 화면 중심을 벗어난다. (2) 중심 reticle만 고정하면 셀 경계와 커서 외곽이 어긋나 어떤 칸에 쓰는지 모호해진다. (3) 카메라를 셀 단위로 이동하고 작은 입력량을 누적하면 한 셀의 중심과 화면 중심을 항상 일치시킬 수 있다. 이번 구현은 3을 선택한다. 셀 단위로 움직이는 촉감은 실험 선택이며, 작은 스크롤을 버리지 않도록 잔여 이동량을 누적한다. 후속 실험은 입력 위치의 명확성을 유지하면서 탐색 촉감을 개선하는 것이다.

**입력 대안:** 전역 keydown만으로 문자를 만들면 OS의 한글 조합·모바일 키보드·붙여넣기 경로를 온전히 활용할 수 없다. 기존처럼 별도 textarea 패널을 두는 방식은 사용자가 명시적으로 제거했다. 따라서 실제 native textarea를 중심 셀에 배치해 포커스·IME 입력을 받되, 별도 시각적 입력창을 만들지 않는다. 조합 중 글자는 중심 셀에서 로컬 미리보기로 그리고, 조합 완료 후에만 공유 세계에 확정한다. 실제 위치가 바뀌거나 주소 보존이 확인되지 않은 epoch 변경으로 취소된 조합을 다른 셀에 기록하지 않는 규칙은 유지한다. 주소가 보존된 자동 크기 변경의 문맥 유지 조건은 D013에 따른다.

**모바일:** 키보드가 뜨면 visualViewport를 기준으로 앱 영역을 맞춰 키보드를 제외한 지도 중심에 커서와 입력 기준점을 유지한다. GPS·공유·줌·도움말은 네이티브 키보드 입력을 가로막지 않는 지도 오버레이로 유지한다. OS 키보드와 한글 후보창은 브라우저·운영체제가 제공한다.

**검증 범위:** 이번 변경은 중심 셀과 viewport 중심의 일치, 가로·세로 탐색에 따른 presence, 직접 입력 후 카메라 추종, 줌·resize·재접속, 한글 조합의 단일 커밋과 취소를 브라우저 테스트에서 확인해야 한다. 실제 실행 결과는 검증 기록에 별도로 남긴다. 모바일 에뮬레이션과 CDP IME를 실제 iOS/Android 키보드 검증으로 간주하지 않는다.


### D009 — 입력 이벤트가 아니라 작성 의도를 유지

2026-11-02 사용자가 Enter 동작을 제품 목적과 기대에 비추어 다시 판단하라고 요청했다. 현재 열 유지, 세계 0열 복귀, 주변 글 추론, 전송/입력 종료, 로컬 작성 기준 열 복귀를 비교했다. [INPUT_DESIGN.md](INPUT_DESIGN.md)에 비교와 기존 실행 반례를 기록한다. `ABC` 뒤 Enter가 계단 모양을 만들고, 동일한 `ABC\nD`가 이벤트를 나눠 받으면 다른 좌표에 배치되는 실패 때문에 로컬 작성 기준 모델을 선택했다. 기존 D001/D005에 기록한 현재 열 다음 행 동작은 이 결정으로 대체한다.

작성 의도·기준 열 규칙은 유지한다. 아래 최초의 키 이벤트 병행과 단어 삭제 제한은 D014에서 정확한 native 범위 기반 처리로 대체했다.

**선택:** 첫 글쓰기의 기준 열을 유지해 Enter·Shift+Enter·모바일 줄바꿈·붙여넣기를 같은 공간 계획으로 처리한다. 원래 쓰던 행의 좌표를 이동시키거나 글자를 밀지 않는다. 줄바꿈만 있으면 presence만 이동하고 DB 쓰기는 만들지 않는다. 클라이언트와 서버가 선택적 `lineStartX`를 공유하고, 이를 생략한 기존 클라이언트 요청은 기존 paste 시작 열로 해석한다.

**탐색과 교정 구분:** 지도 pan·GPS·좌표 링크는 새 장소 선택이므로 기준을 초기화한다. 반면 활성 작성 중 방향키로 오타를 고친 것까지 새 문장의 시작으로 취급하면 같은 판단 오류가 반복된다. 방향키는 작성 전에는 예상 기준을 옮기고, 작성 중에는 기준을 보존하되 과거 역추적 경로를 비운다. Home은 현재 행의 기준 열로 이동한다. 줌·키보드 표시·포커스와 확정된 동일 epoch 재접속은 기준을 보존한다. 주소 보존 조건을 충족한 자동 크기 변경도 D013에 따라 문맥과 기준을 유지한다. 그 밖의 epoch 변경·일반 재동기화·오류 복구·불확실한 입력 복구는 초기화한다.

**Backspace:** 공통 planner가 반환하는 실제 문자/return 전이를 로컬에서 최근 4096개까지 기억한다. Backspace는 문자 전이를 한 칸 지우며 거슬러 가고, return 전이는 어느 셀도 지우지 않고 이전 줄 끝으로 돌아간다. 명시적 커서 이동 뒤에는 세계에서 줄 끝을 추측하지 않고 왼쪽 칸만 삭제한다. 이는 undo나 소유 문단이 아니며 타인의 후속 글을 이전 버전으로 되돌리지 않는다. 경로는 서버에 저장하지 않는다.

**다른 native 입력 의도:** keydown·beforeinput·input의 줄바꿈/삭제를 같은 명령으로 연결했다. IME 확정 Enter를 앱 줄바꿈으로 중복 처리하지 않는다. 범위 선택·복사·잘라내기, 단어/행 삭제, undo/redo, 문맥 없는 자동 치환을 새 글 삽입으로 오인하지 않고 명시적 미지원·무변경으로 처리한다. 이 제한은 지도 입력 수신기에만 적용하며 도움말·브라우저의 선택/복사를 막지 않는다. Tab은 접근성 포커스 이동, 붙여넣은 tab은 공백4칸으로 둔다. 전역 문자열이 없으므로 End가 이동할 줄 끝을 추론하지 않는다.

**한계와 다음 실험:** 이 기준 수명은 실제 사용자 연구로 확정된 사실이 아니다. 시·ASCII 배치·기존 글 오타 수정 과제를 수행하며 기준을 예측하는지 관찰한다. iOS/Android의 IME 확정과 자동 치환 이벤트는 실제 기기 검증이 필요하다. 제품 헌법은 변경하지 않았다.

### D010 — 한글 조합은 OS 입력 문맥을 보존하고 최근 공간 경로에 적용

**역사 기록:** 문맥 보존 원칙은 유지한다. 아래 끝부분 diff·32자 제한·textarea 선택은 D014로 대체했고 현재 구현에는 남기지 않는다.

2026-11-02 사용자가 한글 입력이 낱자로 분리된다고 보고했다. 이미 시작된 한 음절의 조합 완료만 검사한 기존 테스트로는 이 문제를 배제할 수 없었다. 실제 Chromium CDP에서 첫 `ㅎ` 입력 후 OS가 이전 범위를 `하 → 한`으로 조합 교체하면 `ㅎ한`이 남는 반례를 재현했다. 매 input·compositionend 직후 textarea를 비우는 구현이 OS의 교체 범위를 없앴다.

**대안과 선택:** 매 이벤트 뒤 입력창 초기화는 문맥을 끊으므로 기각했다. 앱 내부 한글 조합기 구현은 OS 키보드·후보 선택·다른 언어를 다시 구현하게 되므로 기각했다. textarea 전체를 문서로 동기화하면 셀 삽입·reflow를 유도하므로 기각했다. 네이티브 버퍼를 보존하고 확정 문맥과 새 값의 grapheme 단위 차이만 공간 입력으로 변환한다. 문자 조합은 계속 OS가 담당한다.

**교체 범위:** 현재 커서에서 로컬 작성 경로로 확인할 수 있는 끝부분의 최대 32개 문자만 교체할 수 있다. 명시적인 탐색·편집 명령·일반 재동기화는 네이티브 문맥 경계를 새로 잡는다. 주소 보존 조건을 모두 충족한 자동 크기 변경에서는 D013에 따라 문맥과 작성 경로를 유지한다. 취소된 조합의 늦은 완료와 확정 뒤 companion input은 새 글로 재삽입하지 않는다. 일반 문서형 범위 편집·자동 교정·undo를 지원한다는 뜻은 아니다. 최근 글을 다른 사람이 덮어썼다면 일반 공개 공간의 덮어쓰기 규칙을 적용하며 소유권이나 과거 버전 복원을 만들지 않는다.

**실험 경계:** 32개 한도는 구현 선택이다. Chromium의 native 범위 교체와 이벤트 순서 검사는 실제 iOS·Android 키보드 검증을 대신하지 않는다. 기기별 연속 음절·후보 확정·삭제를 다음 입력 실험으로 남긴다. 실제 실행 결과는 [VERIFICATION.md](VERIFICATION.md)에 기록한다.

### D011 — CJK 표시 폭은 기본 칸의 1배 또는 2배

**후속 변경:** 1/2칸의 공간 폭·시작/연속 셀 규칙은 유지한다. 일반 글꼴과 12×30px 배치는 사용자의 후속 요청에 따라 D015로 대체했다.

사용자는 CJK 고정폭 글꼴의 간격 규칙을 요청하되 그 글꼴 자체를 쓰지는 말라고 했다. 바이트 수는 인코딩마다 달라 표시 기준에서 제외한다. 폰트의 실제 픽셀 폭을 주소로 사용하면 기기별 fallback에 따라 세계 배치가 바뀐다. 저장은 한 칸으로 둔 채 그림만 늘리는 방식은 이웃 글과 겹치고 입력·삭제 위치가 어긋난다.

**선택:** Unicode 17 East Asian Width W/F와 emoji 표시 묶음은 2칸, 반각·중립·ambiguous 문자는 1칸으로 계산한다. 결합 부호는 기저 문자에 폭을 더하지 않는다. 공통 폭 함수를 서버·클라이언트가 사용한다. 실제 글꼴은 Arial·플랫폼 한글 sans-serif를 유지하고 기본 칸은 12×30px로 둔다. D001의 grapheme 하나를 항상 한 칸에 그리는 선택은 새 입력에서 이 결정으로 대체한다.

**공간 표현:** 두 칸 문자는 시작 셀 `{text,width:2}`와 연속 셀 `{text:'',width:0,leadX}`의 쌍이다. 두 셀은 점유·저장·전파되며 어느 절반을 삭제·덮어써도 기존 쌍을 원자적으로 정리한다. 다른 글을 밀지는 않는다. 토러스 경계를 넘는 쌍, 반복 주소 paste, scavenger의 버전 조건도 같은 쌍 규칙을 따른다. 커서는 여전히 기본 칸 하나를 가리킨다.

**데이터와 실험 제한:** 기존 글의 폭을 일괄 확장하면 이웃을 지우거나 밀 수 있으므로 이전 기록은 주소·내용·버전을 유지하고 `width:1`로 읽는다. 새 입력부터 새 폭을 적용한다. SQLite에는 폭 메타데이터를 추가하며 백업·복구 조건은 [DEPLOYMENT.md](DEPLOYMENT.md)에 기록한다. 새 write/erase는 `layout:2`를 요구하고 구클라이언트에는 새로고침을 안내한다. 좌우 경계를 가로지르는 두 칸 문자가 있으면 너비 변경을 보류한다. 이 보류는 쌍의 인접성을 보존하는 현재 단축 선택이며 영구 크기 적응 알고리즘은 아니다.

**다음:** 혼합 한글·영문·emoji의 읽기와 수정 과제에서 표시 폭을 검증하고, 좌표·인접성을 함께 보존하는 resize 모델을 다시 비교한다. Unicode 버전 갱신은 공유 세계 배치를 바꿀 수 있으므로 데이터 파일과 버전을 명시적으로 관리한다.

### D012 — 드래그 관성은 추가하고 휠의 OS 관성은 중복하지 않음

**후속 변경:** fling과 OS wheel 총량의 구분은 유지한다. 아래 셀 단위 카메라·항상 중심 선택은 D017의 연속 화면 이동·정지 시 중심 재정착으로 대체했다.

**대안:** 즉시 정지는 기존의 딱딱한 탐색 촉감을 남긴다. 모든 이동에 동일한 fling을 더하면 OS가 이미 감속하는 트랙패드 wheel의 이동을 중복 증폭한다. 완전한 fractional 카메라로 바꾸면 셀 중심과 화면 중심의 일치를 다시 설계해야 한다.

**선택:** 마우스·터치 드래그를 놓을 때 최근 속도에 지수 감속을 적용한다. wheel은 전달받은 이동량만 짧게 평활화하고 총량을 유지한다. 관성도 기존 픽셀 누적기와 기본 칸 주소 이동을 사용하므로 커서 중심 불변식과 원격 presence 경로를 공유한다. 타이핑·IME 시작·새 제스처·줌·GPS·좌표 링크·도움말·연결 중단·resize·탭 숨김에서는 남은 관성을 버린다. 핀치의 이전 속도를 남은 손가락에 재사용하지 않는다. reduced-motion에서는 fling을 끄고 wheel을 즉시 전달한다.

**실험값과 실패:** 속도 추정 최근 80ms, 감속 시정수 220ms, 최대 꼬리 1400ms, wheel 평활화 45ms를 초기값으로 둔다. 실제 Chromium 검증에서 RAF timestamp가 같은 프레임의 pointerup 시각보다 이를 수 있어 관성이 즉시 취소되는 실패를 발견했다. 하나의 단조시계로 시간을 읽도록 바꾸었다. 프레임률 독립 이동과 긴 중단 뒤 점프 방지는 유지한다. 셀 단위 이동의 촉감과 감속 수치는 실기기에서 후속 조정한다. 이 선택도 제품 헌법을 변경하지 않는다.


### D013 — epoch 변화와 작성 주소의 변화를 구분

**실제 배포에서 발견한 실패:** D010의 네이티브 버퍼 보존 수정 후 첫 Railway 공개 검증에서도 `ㅎ`를 `한`으로 고치는 데 실패했다. 재시도는 통과했고 그 사이 세계 epoch 변경을 확인했다. 이를 단서로 `ㅎ` 확정과 다음 조합 사이에 주소가 그대로인 density resize를 넣어 `ㅎ한` 중복을 로컬에서 재현했다. snapshot 수신 코드가 버퍼를 비우는 별도 원인을 확인했다. 입력 모듈이 문맥을 유지하는 것만으로는 충분하지 않았고, 세계 갱신과 조합이 겹치는 경우를 기존 검사에서 놓쳤다.

**재판단:** 모든 epoch 변경에서 문맥을 버리면 위치가 그대로인 자동 확장도 사용자의 한글 입력을 끊는다. 모든 snapshot에서 문맥을 유지하면 실제 위치 변경·오류 복구·미확정 쓰기를 과거 입력 범위와 잘못 연결한다. 따라서 epoch 숫자만으로 판단하지 않고 서버의 주소 보존 보장과 클라이언트의 현재 작성 상태를 함께 확인한다.

**선택:** 현재 서버 resize는 점유된 주소를 옮기지 않고 빈 가장자리 영역만 추가·제거한다. 이 변경의 성공 결과에만 `preservesAddresses:true`를 보낸다. 클라이언트는 살아 있는 연결의 `density-resize` snapshot이고, 해당 표시가 있으며, pending 쓰기가 없고, 본인 session ID와 커서 좌표가 같고, 작성 기준 열 및 역추적 경로의 모든 좌표가 새 범위에 들어가며 각 문자 진행·줄바꿈의 인접성도 유지될 때만 네이티브 버퍼·조합 미리보기·작성 기준·경로를 보존한다. 최종 조합 확정은 새 세계·epoch를 사용한다. 예를 들어 128열 세계에서 126→0으로 진행한 기록은 256열로 늘어나면 더 이상 같은 인접 관계가 아니므로 보존 대상에서 제외한다.

**계속 초기화하는 경우:** 일반 sync·오류 복구·실제 위치 이동·결과가 불확실한 쓰기·주소 보존을 확인할 수 없는 epoch 변경에서는 이전 문맥을 취소한다. 재접속 때의 기존 작성 기준 보존 규칙과, 연결 중 주소 보존 resize에서 네이티브 조합을 보존하는 규칙은 구분한다. 미래의 remap resize가 현재의 주소 보존 표시를 그대로 재사용해서는 안 된다.

**검증과 한계:** 첫 자모 확정 뒤 자동 resize, 조합 진행 중 자동 resize, 일반 sync·불확실한 쓰기의 취소를 각각 검사해야 한다. 실제 실행 결과와 공개 재배포 검증은 [VERIFICATION.md](VERIFICATION.md), [DEPLOYMENT.md](DEPLOYMENT.md)에 기록한다. 주소 보존은 미래의 모든 토폴로지 변환에 대한 약속이 아니며, 제품 헌법은 변경하지 않았다.

### D014 — 키와 문자열 차이 대신 native 편집 범위를 공간에 투영

**문제:** 문맥을 유지하는 D010만으로 정확한 교체 위치가 생기지는 않는다. 접두사·마지막 문자 비교는 반복 문자열이나 중간 재변환에서 범위를 추측하고, 최대 32자라는 제한은 그 불확실성을 해결하지 않는다. 사용자는 여러 나라의 사례와 표준을 조사하고 최신 브라우저를 대상으로 입력 처리를 정리하되 폴백·레거시 처리는 만들지 말라고 요청했다.

**조사와 대안:** [W3C·벤더 조사](research/IME_STANDARDS.md), [한국어·일본어·중국어 개발 사례](research/IME_LOCAL_PRACTICE.md)를 대조했다. textarea는 native 조합을 지원하지만 `getTargetRanges()`가 빈 배열이어서 selection/value의 별도 모델이 필요하다. EditContext는 canvas에 맞는 정확한 범위 갱신을 제공하지만 조회 시점의 최신 Safari·Firefox가 지원하지 않아 보류했다. 처음 선택한 `contenteditable="plaintext-only"`는 세 엔진의 속성 지원만으로 충분하다고 판단했으나, Chromium 154에서 실제 타이핑·삭제·조합의 target ranges가 비었다. Blink의 `TargetRangesForInputEvent()`가 richly editable에만 범위를 제공하는 공식 구현도 확인했다. 이 반례에 따라 초기 선택을 바꿨다.

**선택:** `contenteditable="true"`에 plain-text 정책을 적용한 호스트 하나를 사용한다. `beforeinput`의 StaticRange를 UTF-16 offset으로 복사하고 `input`에서 실제 DOM 결과를 확인한다. `compositionstart/end`로 native 거래의 수명을 관리한다. 서식은 거부하고 붙여넣기는 `text/plain`만 받는다. Enter·삭제는 편집 의도로 처리하며 `keydown`은 지도 탐색·명시적인 미지원 단축키에 제한한다. 키 코드 분기, 암묵적 조합 추정, 종료 직후 타이머, 타입 없는 입력 허용, 끝부분 diff는 제거한다. 관측한 시작 없이 도착한 조합 초안을 일반 확정 입력으로 발행하지 않는다.

**공간 변환:** `NativeProjection`은 원문 UTF-16 범위 → grapheme → 점유 셀 주소를 연결한다. 조합 중 원문을 정규화하지 않고 확정된 세계 쓰기에서만 공통 Unicode 규칙을 적용한다. 알려진 문맥의 단어 삭제·중간 재변환을 허용하되 변경되지 않은 suffix의 세계 좌표는 유지한다. 긴 대체문이 그 셀에 닿으면 일반 덮어쓰기이며, 겹친 옛 문맥 매핑은 이후 편집에 재사용하지 않는다. 세계의 임의 선택·복사·잘라내기·undo는 지원하지 않는다. 정확한 native 범위가 없으면 diff로 만들어내지 않고 거부한다.

**원자적 변경과 취소:** 지울 주소 `write.clear`와 대체 텍스트를 같은 요청으로 보내며 서버는 삭제·쓰기·두 칸 문자 정리를 한 트랜잭션·패치로 적용한다. 활성 조합 중 이동·오류 복구는 거래를 무효화하고 미리보기만 숨긴다. OS가 소유한 DOM은 조합 종료까지 보존한 뒤 버린다. D013의 안전한 density resize 조건은 유지하고, epoch가 바뀌었다는 이유만으로 조합을 끊지 않는다.

**실험 경계:** 32자 제한은 제거했다. 이 단계에서는 한 번의 세계 텍스트를 512 grapheme·4096 UTF-16 단위, 명시적 정리 주소를 2048개로 제한했다. 공개 참여자의 입력·치환 한도는 이후 D018의 공통 행동 정책으로 대체한다. 겹친 문맥에 대한 추가 편집은 지도를 움직여 새 문맥을 만들기 전까지 거부한다. 현대 브라우저에서도 beforeinput·유효 범위가 누락되는 경로는 있으므로 이 선택을 모든 OS 키보드 지원 완료로 해석하지 않는다. 실행 증거는 [VERIFICATION.md](VERIFICATION.md)에 두고, 실제 Windows/macOS/Android/iOS의 한국어·일본어·중국어 후보 선택과 재변환을 다음 실험으로 남긴다.

### D015 — 실제 CJK 고정폭 글꼴로 한글·영문 간격을 함께 축소

**권한과 목표:** 사용자는 한글·영문 모두 더 촘촘한 간격을 요청했고, 후속 지시에서 이전의 일반 글꼴 조건을 바꾸어 CJK를 지원하는 monospace 계열을 직접 적용하도록 했다. D011의 일반 글꼴 선택은 이 후속 요청으로 대체한다. 제품 헌법이나 세계의 1/2칸 주소 규칙은 바꾸지 않는다.

**대안:** 시스템 `monospace`는 기기마다 CJK 대체 글꼴과 간격이 달라진다. Noto Sans Mono CJK는 적합한 대안이다. Sarasa Mono K는 전각 em dash와 ligature가 있어 현재의 ambiguous=1·grapheme별 배치와 조정할 항목이 있다. [공식 자료와 실측](research/CJK_FONT.md)을 근거로 ligature가 없고 em dash가 반각인 **Sarasa Fixed K Regular 1.0.43**을 선택했다. 한국어 지역 자형을 기본으로 하며 일본어·중국어 문자도 포함한다.

**선택과 표시:** 18px 글꼴의 본래 반각 advance 9px·CJK advance 18px를 사용하고 행 높이는 26px로 둔다. 이전 12px·24px보다 가로 간격을 모두 25% 줄인다. `fillText`의 maxWidth 압축은 제거해 글자 형태를 보존한다. 기존에 `width:1`로 저장된 넓은 글자는 그 한 칸의 주소를 지키면서 작은 글꼴 크기로 그린다. 새 입력은 공통 1/2칸 규칙을 적용한다.

**배포와 비용:** 전체 Regular 파일을 glyph·advance 변경 없이 WOFF2로 변환해 자체 제공한다. 5,315,944 bytes(약 5.07 MiB)이며 [OFL·출처·해시](../public/fonts/README.md)를 동봉한다. 버전 파일은 immutable 캐시하고 글꼴 로드 뒤 세계에 연결한다. 로딩 실패를 시스템 글꼴로 숨기지 않는다. 초기 다운로드 비용과 모든 Unicode·emoji를 포함하지 않는 범위는 남은 제한이다. 국가별 한자 자형의 자동 선택이나 glyph subset 분할은 이번에 추가하지 않았다.

**다음 실험:** 실제 모바일 첫 접속의 로딩 시간과 9/18px 혼합 행 가독성을 관찰한다. 문자를 누락하지 않는 분할 다운로드가 필요한지는 이 결과로 판단한다. 폰트 측정과 렌더링 확인은 입력기 검증과 구분하며 구체적인 실행 결과는 [VERIFICATION.md](VERIFICATION.md)에 기록한다.

### D016 — 실제 native 조합 표시와 즉시 로컬 반영으로 타이핑 지연을 줄임

**문제와 측정:** 사용자가 타이핑할 때의 움찔거림·느린 반응을 지적하고 native input을 더 잘 활용하라고 요청했다. 기존 경로는 조합을 Canvas에서 다시 그리고, 완료 순간에는 초안을 지운 뒤 서버 셀 패치를 기다렸다. 그 사이 커서·카메라만 진행해 글자가 비는 시간이 생겼다. 서버 응답을 300ms 늦춘 계측에서 입력 후 해당 글자를 포함한 첫 Canvas draw 시작은 ASCII 약 318.7ms, 한글 약 319.1ms였다. 전체 draw 완료나 화면 표시 장치의 scanout 시간을 잰 값은 아니다.

**대안 비교:** 전체 native 버퍼를 화면에 그대로 노출하면 일반 문서처럼 이어지는 prefix/suffix가 공간상의 고정 좌표와 어긋난다. 중간 치환 뒤 뒷글의 좌표 보존, torus 경계, 원격 덮어쓰기와 충돌하므로 기각했다. Canvas에 조합 렌더러를 더 만드는 대신 기존 native 요소의 현재 조합 부분을 직접 보여주는 방식을 선택했다. 완료 입력을 계속 서버 확인까지 숨기는 방법도 지연의 원인을 남기므로 바꿨다.

**선택:** `native-surface.js`가 현재 native DOM Range의 사각형을 읽고 CSS clip·transform만 바꿔 활성 조합 범위를 지도 위에 표시한다. 조합 DOM·선택을 재작성하거나 글자를 복제하지 않는다. Canvas 초안 렌더링을 제거하고 DOM 커서를 실제 세계 셀에 붙인다. 커서·native 표면·Canvas는 D017의 같은 카메라 좌표를 따른다.

**완료 입력의 표시:** `local-world.js`는 전송한 쓰기·삭제를 즉시 로컬 셀에 투영한다. 서버 확정 셀과 미확정 작업을 분리하고, 새 패치가 오면 확정 셀 위에 남은 작업만 다시 적용한다. 자신의 echo·ack는 해당 작업을 제거하며 최종 경쟁 결과는 서버 순서를 따른다. 오류·단절·snapshot에서 과거 셀 값으로 되돌리는 rollback을 하지 않아 다른 사람의 글을 덮거나 오래된 입력을 되살리지 않는다. 조합 초안은 계속 로컬에만 존재한다.

**발견한 추가 실패:** 긴 native 조합이 `overflow:hidden`인 조상을 caret 노출용으로 스크롤해 Canvas의 left가 실험 중 −1196px·−8395px까지 밀렸다. 앱·viewport를 `overflow:clip`으로 바꾸어 스크롤 컨테이너가 생기지 않게 했다. 이는 입력 호스트의 값이나 선택을 강제로 되돌리는 패치와 구분한다.

**증거와 경계:** 즉시 로컬 반영을 적용한 중간 단계의 같은 300ms 지연 fixture에서는 첫 Canvas draw 시작이 ASCII 약 17.9ms, 한글 약 5.3ms였다. 증거는 `artifacts/typing-latency-baseline.json`, `artifacts/typing-latency-after.json`이며 최종 코드 검증·실행 조건은 [VERIFICATION.md](VERIFICATION.md)에 기록한다. 단일 프로토타입 측정값으로 모든 기기의 지연을 보장하지 않는다. 실제 OS 및 Safari·Firefox 검증은 남아 있고, 여러 행 조합이 비연속 공간 주소를 가로지르는 경우 native 사각형의 초안 배치에 한계가 있다. 확정 주소 계산은 공간 투영기가 담당한다.

### D017 — 부드러운 이동을 우선하고 정지하면 중심에 재정착

**변경된 우선순위:** 사용자는 키보드 높이가 급변할 때의 지도 점프와 일반 스크롤을 부드럽게 만들고, 커서가 잠시 중심에서 벗어나도 부드러움을 우선하라고 명시했다. 따라서 D008/D012의 매 순간 중심 일치 선택을 변경한다. 커서·입력 주소·presence는 실제 정수 셀을 가리키며, 화면 카메라만 연속적으로 움직여 정지 시 중심에 놓인다. 입력 후 글자 폭만큼 진행하는 동작이나 지도 이동 자체를 제거하지 않는다. 제품 헌법은 수정하지 않는다.

**전환 모델:** viewport 경계는 키보드를 피해 즉시 갱신하고 카메라가 새 중심을 부드럽게 따라간다. 경계 크기까지 늦게 바꾸는 안은 키보드 뒤에 UI를 남길 수 있어 택하지 않았다. 큰 축소로 커서가 가려지면 화면 안으로 들어올 최소 거리만 먼저 보정한다. 초기 시정수는 viewport 110ms(약 330ms에 거리의 95%), 타이핑 80ms, wheel 카메라 50ms다. 기존 wheel 이동량의 45ms 평활화와는 별개이며 OS 관성을 중복하지 않는다. reduced-motion은 즉시 정착한다.

**직접 조작과 경계:** 드래그는 소수 칸 단위로 손가락을 즉시 따른다. 진행 중인 전환을 잡으면 현재 보이는 카메라를 멈추고 중심과의 차이를 유지해 잡는 순간 뛰지 않는다. 놓은 뒤 관성과 중심 재정착을 이어 가며, 입력 등으로 pan을 중단한 경우에도 정착시킨다. torus에서는 연속된 경로로 이동해 반대편까지 한 바퀴 도는 애니메이션을 피한다. 큰 GPS·주소 이동이나 topology 전환은 별도의 즉시 재배치 경계다.

**그리기 비용의 재평가:** 부드러운 카메라는 그리는 횟수를 늘리므로 카메라 RAF와 일반 RAF가 같은 프레임에 중복 draw를 만들지 않게 했다. 별도 glyph 비트맵 캐시는 DPR 1의 4760 glyph fixture에서 기존 약 10.4~12.1ms를 32.9~33.2ms로 악화해 기각했다. 폭 계산 메모와 텍스트 pass의 스타일 일괄 설정·변경 시에만 font 설정을 하는 단순 방식은 같은 fixture에서 약 7.0~7.6ms, 24종 혼합 글자 fixture에서 약 8.6~9.8ms를 5.0~5.7ms로 줄여 적용했다. 복잡한 캐시 엔진은 추가하지 않았다. 이는 해당 로컬 DPR 1 실험값이며, DPR 2는 변동이 커 개선을 확정하지 않는다.

**다음 실험:** 실제 모바일 키보드의 높이·후보창 변경과 빠른 스크롤·드래그 재시작을 검증한다. 글자가 밀집한 지도의 최종 프레임 시간과 다양한 DPR·저성능 기기의 체감을 측정해 가벼운 그리기 개선부터 비교한다. 계측의 draw 시작·CPU draw 시간·실제 화면 표시를 구분하고 최신 결과는 [VERIFICATION.md](VERIFICATION.md)에 기록한다.

### D018 — 참여자 권한의 경계를 서버의 커서·시야·행동 예산에 둠

2026-11-02 사용자는 봇·에이전트의 공개 참여를 요청하면서 사람보다 많은 권한이나 순간적인 대량 입력·전체 범위 파악 능력을 주지 말라고 했다. 이어 비정상적인 입력 빈도에는 `429`를 명시했다. 공개는 사전 계정·키 발급 없이 참여한다는 뜻으로 적용하며, 무제한 행동 능력으로 해석하지 않는다. 제품 헌법은 변경하지 않는다.

**기존 경로의 실패:** 새 봇 API에만 제한을 붙이면 프로그램이 브라우저 `/ws`로 접속해 우회할 수 있다. 이전 경로 분석 실험에서 512자 쓰기 40건으로 약 0.5초에 20,480칸을 바꿀 수 있었고 초기 연결·sync·일반 방송도 전체 세계를 노출했다. “브라우저용”이라는 이름이 참여자의 실제 능력을 제한하지 못했다.

**대안:** 봇 API만 제한하는 안은 우회 경로를 남기므로 기각했다. 모든 클라이언트를 계정·API 키로 구분하는 안은 첫 공개 참여 요구보다 큰 진입 장벽과 동일인 판별 문제를 만든다. 모든 문자 입력을 한 글자씩 강제로 보내는 안은 IME 확정·재변환을 분해하고 통신을 늘린다. 현재 커서와 최근 입력 문맥을 서버가 확인하고, 모든 공개 전송 경로에 같은 제한을 적용하는 안을 선택했다.

**쓰기와 이동:** 참여자는 자신의 커서 또는 서버가 알고 있는 최근 입력 문맥의 시작점에서만 쓴다. 임의 원격 좌표와 임의 `clear` 목록을 받지 않는다. 서버가 최근 승인한 최대 512개 주소의 native 입력 문맥은 화면 밖까지 재변환할 수 있게 하되, 한 번의 64 grapheme 한도와 같은 쓰기 예산을 적용한다. 일반 탐색을 하면 그 입력 문맥을 지운다. 현재 자리에서 공통 문자 배치 규칙으로 만들어지는 짧은 쓰기 경로도 시야 끝을 넘어갈 수 있게 해 긴 IME 확정을 화면 폭 때문에 거부하지 않는다. 이 경로를 실행해도 중간 화면·원래 범위를 추가로 관측하지 않으며, 임의 원격 주소 쓰기 권한이 생기지 않는다. Backspace는 현재 위치 바로 앞의 완전한 글자만 지우거나 이미 알려진 작성 경로를 따른다. 이동은 토러스 최단 거리를 예산으로 계산하며 큰 GPS·공유 좌표 이동도 예산을 소모한다.

**시야:** 처음 연결, sync, 크기 변경, 일반 글자·커서 전파를 모두 커서 중심의 제한된 관측으로 바꾼다. 기본 80×24, 최대 320열·128행·24,576칸은 초기 화면 실험값이다. 현재 시야의 빈 주소도 정보이므로 새로 읽는 모든 주소를 계산한다. 두 칸 글자는 경계에서 인접한 반쪽까지 전달하고 비용에 포함한다. 시야 밖 작성자·출처·갱신 이력과 다른 커서는 노출하지 않는다. 현재 관측과 한 개의 비교 기준만 유지하며 전 세계 변경 이력이나 이동 경로의 모든 화면을 반환하지 않는다. 작은 세계 전체가 한 화면에 들어오는 것은 허용된 화면 크기의 결과다.

**속도와 실험값:** 참여자 쓰기는 초당 12 grapheme 보충·일시 여유 64 grapheme, 단일 확정도 최대 64 grapheme으로 둔다. 네트워크 공통 예산도 적용하고 연결이 끊겨도 최소 10분 유지해 재접속으로 순간 여유를 새로 얻지 못하게 한다. 이 64자 여유는 한·중·일 IME 후보 확정과 짧은 붙여넣기를 보존하기 위한 가설이며 영구 정책이 아니다. 원문 바이트 수나 CJK의 두 칸 폭을 타이핑 능력으로 혼동하지 않는다. 참여자·네트워크의 요청·이동·새 관측 예산은 별도로 계산하며, 일시 부족은 `429`, 요청 자체가 한도를 넘으면 `413`이다. WebSocket 업그레이드 뒤에는 HTTP 상태를 보낼 수 없어 동일한 `status:429`·대기 시간을 메시지로 전달한다.

**남은 위험과 다음 실험:** 같은 NAT의 정상 사용자도 공통 예산·동시 8세션 한도를 공유한다. 여러 네트워크에 분산한 봇을 동일인으로 묶을 수 없으며 이 제한을 완전한 abuse 대응으로 주장하지 않는다. 정상적인 빠른 입력·IME 대량 확정·지도 fling과 여러 봇의 상호 덮어쓰기 과제를 함께 측정해 오탐률과 실제 화면 관측 속도를 비교한다. 전체 세계를 매번 보내던 기존 성능 가정도 시야 크기·동시 참여자 수를 늘려 다시 측정한다.

### D019 — HTTP 행동 묶음을 받아 서버 시간에 따라 실행

**대안:** 글자마다 REST 요청을 보내면 도구 호출·네트워크 지연이 타이핑 속도와 비용을 결정한다. WebSocket을 봇에게 그대로 문서화하면 프로그램에는 효율적이지만 각 에이전트가 입력 간격·변경 구독·재연결 상태를 다시 구현해야 한다. 대량 문자열을 한 번에 원자적으로 적용하는 API는 통신 비용만 줄이고 순간 능력을 높인다. 서버가 제한된 행동 묶음을 받아 일정 속도로 실행하고 마지막의 현재 관측을 반환하는 방식을 선택했다. 별도의 관리자급 도구나 전체 세계 조회 권한은 추가하지 않는다.

**선택:** 익명 `POST /api/agents/v1/sessions`가 공개 커서 ID와 별도의 비밀 임시 토큰을 발급한다. 토큰은 Bearer 헤더로만 전달하고 공개 presence에 섞지 않는다. 한 행동 묶음은 최대 16개 행동·256 grapheme·4096 UTF-16 단위·예정 30초다. `type`, 상대 `move`, `enter`, `backspace`, `delete`, `home`, `wait`를 제공한다. 서버가 초당 10 grapheme·160칸 이동으로 실행하고 각 효과는 D018의 공통 정책을 통과한다. 연속된 한 글자 요청 사이에도 다음 실행 시각을 유지해 묶음을 나누는 우회를 막는다. 사람은 실행 중인 봇의 커서와 글자를 일반 참여자처럼 본다.

**관측 효율:** 빈 행동 요청은 현재 관측 또는 최대 25초의 변경 대기를 제공한다. 시야 밖 변화로는 응답하지 않는다. 세션당 동시 실행·관측 하나만 유지하고, 진행 중 묶음의 같은 ID 재조회에는 `202`와 진행 요약만 준다. 중간 시야를 반복 수집하는 별도 읽기 통로는 만들지 않는다. 완료·취소·실패 응답은 현재 시야의 변화만 돌려주며 오래된 revision에는 현재 화면을 다시 보낸다.

**부분 실패와 중복:** 모든 행동의 형식과 최대 실행량을 먼저 검사하지만, 실제 예산 부족·epoch 변경은 실행 도중에도 발생할 수 있다. 그 경우 실행된 단계·행동 수와 `blocked` 상태를 반환한다. 이미 쓴 셀을 과거 값으로 되돌리지 않는다. 같은 ID·같은 행동의 재요청은 재실행하지 않고 진행 또는 완료 요약을 반환한다. 최근 16개 완료 요약과 사용한 ID 최대 1,024개만 보관하고, 요약이 사라진 ID는 명시적으로 거절한다. 관측은 ID를 소비하지 않는다. SDK는 부분 결과를 반영한 후 오류를 알리고 전체 쓰기를 자동 재전송하지 않는다.

**취소·수명:** 취소와 세션 삭제는 쓰기·요청 예산과 분리해 과부하 중에도 남은 행동을 멈출 수 있게 한다. HTTP 대기를 중단하는 것과 서버 실행 취소는 별개다. 유휴 120초 후 세션을 제거한다. 세션·예약·중복 요약은 메모리에만 있으며 서버 재시작 뒤 복구하지 않는 초기 단축 선택이다. 셀의 영구 저장 경로는 기존 엔진을 유지한다.

**검증과 다음 실험:** 공통 정책과 HTTP·WebSocket 경계는 자동 검증 대상으로 두며 실제 실행 결과는 [VERIFICATION.md](VERIFICATION.md)에 기록한다. SDK 실제 두 세션으로 한글 입력·관측 대기·커서 제거·중간 취소를 확인했다. 다음 실험은 실제 에이전트가 제한된 시야에서 짧은 공동 작업을 수행하게 해 행동 묶음 크기, 취소 반응, `429` 복구와 네트워크 왕복 수를 측정하는 것이다. 현재 정책 숫자와 HTTP 표현은 이 결과에 따라 바꿀 수 있다.

### D020 — 공개 Streamable HTTP MCP를 기존 참여자 API의 얇은 래퍼로 제공

사용자가 기존 에이전트 인터페이스를 MCP로 감싸 달라고 요청했다. MCP 연결 자체가 세계 참여나 쓰기 권한 확대를 의미하지 않게 하고, 기존 D018/D019의 제한과 실행 의미를 유지한다. 제품 헌법은 변경하지 않는다.

**대안:** 로컬 stdio 전용 서버는 모든 사용자가 프로그램을 설치·실행해야 하므로 공개 URL로 연결하는 목적에 맞지 않는다. MCP 전송 세션마다 별도의 참여자 상태를 만들면 초기화·재접속이 커서 생성과 결합하고 HTTP API와 다른 수명·중복 규칙을 유지해야 한다. MCP 도구에서 세계 엔진을 직접 호출하면 같은 제한을 다시 구현하거나 우회할 가능성이 생긴다. 공식 SDK의 stateless Streamable HTTP 전송을 `/mcp`에 두고, 각 도구가 기존 참여자 API를 같은 프로세스 안에서 호출하는 방식을 선택했다.

**도구와 수명:** `textworld_join`, `textworld_look`, `textworld_act`, `textworld_cancel`, `textworld_leave` 다섯 도구를 제공한다. MCP 초기화·도구 목록 조회는 커서를 만들지 않는다. join이 기존 익명 세션을 만들고 공개 ID와 비밀 토큰을 돌려준다. 이후 도구가 그 세션 정보를 명시적으로 받으므로 MCP 전송 연결을 다시 맺어도 유효한 기존 참여자를 제어할 수 있다. MCP 연결 종료와 세계에서 나가는 행동은 별개이며 leave 또는 기존 유휴 만료로 정리한다. 세계 상태와 예약 실행을 별도로 복제하지 않는다. 행동 도구는 다른 사람의 셀도 덮어쓰는 공개 공간의 수정 작업이라는 도구 주석을 제공하며 읽기 전용으로 표시하지 않는다.

**공통 권한과 비용:** 래퍼는 원래 요청의 접속 주소를 보존하고 기존 HTTP API·공통 정책을 호출한다. 내부 어댑터에서 새 네트워크 연결을 만들어 모든 참여자를 서버 자신으로 잘못 집계하지 않는다. 초기화·도구 조회를 포함한 MCP 요청 폭주도 입구에서 제한하고, 내부 호출은 이미 계산한 요청 비용을 중복 부과하지 않는다. 입력·이동·관측과 세션 생성의 각 예산은 기존 경로에서 적용한다. 취소·종료는 예산 소진 뒤에도 가능하도록 요청 제한의 예외로 두되 세션 토큰 인증은 유지한다. MCP를 선택했다고 전체 세계 읽기나 순간 일괄 쓰기 권한이 생기지 않는다.

**오류 표현:** 기존 HTTP API는 과도한 행동에 실제 HTTP `429`를 반환한다. MCP 도구 실행 중 생긴 참여자 오류는 MCP 규약에 맞춰 도구 결과의 `isError`와 구조화된 `status`·`body`로 전달한다. 이때 JSON-RPC 응답을 운반하는 HTTP는 성공할 수 있으므로 MCP 도구 결과의 `status:429`도 확인해야 한다. MCP 입구 자체의 요청 폭주는 실제 HTTP `429`와 `Retry-After`다. 부분 실행 요약과 같은 행동 ID의 중복 방지 의미를 보존하며, 실패한 행동 전체를 자동 재전송하지 않는다.

**의존성과 다음 실험:** 공식 `@modelcontextprotocol/server` 2.4.0·`@modelcontextprotocol/node` 2.1.2와 스키마 검증용 Zod를 사용한다. 예제·테스트는 공식 `@modelcontextprotocol/client` 2.4.0을 사용한다. stdio 브리지·구형 SSE 전송·서버 주도 알림·별도 OAuth 계정은 이번 범위에 넣지 않는다. 공식 클라이언트로 초기화·도구 발견·두 참여자의 입력·관측·취소·오류 전달을 검증하고, 구체적인 실행 증거는 [VERIFICATION.md](VERIFICATION.md)에 기록한다. 다음 실험은 실제 MCP 호스트에서 도구 발견, 임시 세션 핸들 보관, `429` 이후 계획 수정이 자연스럽게 이어지는지 확인하는 것이다.

### D021 — 칸의 변경 번호로 공유하는 신선도, 희소한 시간 표식

사용자는 사람도 새 글과 옛 글을 구분하기 어렵다고 지적했고 글자·좌표의 신선도를 시각화하되 정확한 시각은 불필요하다고 했다. 이어 칸마다 시각을 저장하는 방식의 확장 비용을 피하라고 명시했다.

**비교:** 수신 순간부터 강조하면 처음 방문하거나 재접속했을 때 옛 글도 새 글처럼 보인다. 칸별 timestamp를 새로 추가하면 공간 크기와 문자 수에 비례해 시각 데이터를 중복한다. 연결된 문장·영역 전체에 나이를 붙이면 일부만 덮어쓴 경우 신선도가 부정확하다. 기존 칸별 version으로 변경 구간의 공통 시간을 참조하고, 현재 보이는 변경 번호별 신선도 표를 전달하는 안을 선택했다.

**저장:** 새 칸 필드는 추가하지 않는다. `change_times`는 변경 시퀀스 구간의 시작과 공통 시각만 저장한다. 활성 쓰기가 이어져도 5초 안의 여러 commit은 시간 표식 하나를 공유하고, 다음 구간에서만 새 표식을 쓴다. 칸·history의 기존 updatedAt 컬럼은 이전 스키마와의 구조 호환을 위해0으로 유지하고 실제 시각은 반복 저장하지 않는다(SQLite0은 숫자 payload 없음). 새 중복 방지 결과에도 칸별 시각을 저장하지 않는다. 조회 시 공통 표식으로 복원한다. 현재 엔진의 내부 셀 객체에는 기존 API 호환을 위해 계산한 updatedAt이 남는다. 완전한 메모리 배치 정규화·history 보존 정책까지 해결한 것으로 해석하지 않는다.

**전송:** 공개 셀은 기존 `{x,y,text,width,leadX,version}` 그대로다. 관측마다 `freshness:{version:band}`를 한 번 전송하며 구체적 시각은 노출하지 않는다. 신선도는 now/recent/minutes/earlier/old의5단계다. 최근 지워진 좌표는5분 동안 `marks:[{x,y,version}]`로 표시한다. 저장된 빈 셀을 이용하므로 별도의 삭제 이력이나 칸별 타이머를 만들지 않는다. 모든 정보는 기존 현재 시야 안으로 제한하며 HTTP·MCP와 브라우저가 같은 정보를 받는다.

**표시:** 최근 글은 금색 배경·밑줄로 강조하며 오래될수록 강조를 줄인다. 오래된 글의 가독성을 유지하고 색 외에도 밑줄·배경의 유무로 구분한다. 15초/1분/5분/1시간 경계는 임시 운영값이다. 빈 좌표의 최근 삭제도 옅은 흔적으로 표시한다. 5초 tick에서 다음 경계가 도래한 시야만 갱신하며 글자·버전이 바뀌지 않으면 본문을 다시 보내지 않는다. 신선도 갱신은 IME 문맥을 초기화하지 않는다.

**이전 데이터:** 기존 DB는 변경 전 VACUUM INTO 백업·동기화 후 구간 표로 이전하고, 좌표·본문·폭·버전을 유지한다. 기존 이력의 시각은 먼저 정확하게 옮겨 보존하고 새 쓰기부터 희소한 구간을 적용한다. 이전 서버는0인 기존 컬럼을 실제 시각으로 오해하므로 이 변경 전 코드로 단순 롤백하면 안 된다. 다음 실험은 실제 공동 대화에서 강조 지속 시간과 대비가 새 발화를 찾기에 적절한지 확인하는 것이다. 제품 헌법은 변경하지 않았다.

### D022 — 작업량·자원·비용을 잇는 고정 차원의 누적 계측

사용자는 확장 가능한 규모와 필요한 비용, 개선 방법·결과를 판단할 잠재적 자료를 지속적으로 쌓으라고 요청했다. 요청별 로그/전체 trace의 무제한 보관은 데이터 비용과 식별자 cardinality를 키운다. 외부 관측 SaaS를 즉시 도입하는 대신, 현재 단일 서버에서 고정 항목·합칠 수 있는 histogram·분/시간 집계를 별도 SQLite에 제한 보관하는 안을 선택했다. 운영 지표, 클라이언트 보고, 통제된 실험을 구분한다.

commit·관측·전파의 작업량, CPU/RSS/event-loop, peer 시간, 논리 egress, DB/WAL/계측 자체 비용, 상태·취소를 revision과 연결한다. 본문·좌표·IP·이름·토큰은 기록하지 않는다. 브라우저 보고는 별도 분류·검증·제한하고 계측 실패가 세계를 멈추지 않게 한다. 메모리/보존행/DB 크기 상한을 둔다. 계측 자체의 overhead도 켬/끔 실험과 flush 시간·DB 크기로 확인한다.

단일 짧은 테스트의 p95를 인원 한도로 해석하거나 application bytes를 청구액과 동일시하지 않는다. 로컬 fixture의 원 집계와 환경·코드·반복 실행 편차를 보존하고 공식 플랫폼 자원 지표/가격과 대조한다. 정책 한도·대기시간·계산 지연을 구분한다. 자세한 계량 정의·보존·보고 명령·다음 실험은 MEASUREMENTS.md에 둔다. 향후 다중 서버에서는 호스트 차원과 수집기를 추가해야 하며 현재 통계가 분산 authority 구현을 대신하지 않는다. 제품 헌법은 변경하지 않았다.


### D023 — 빈칸을 선호하되 파괴를 허용하는 분산 무작위 크기 변경

사용자는 확장·축소 중 글의 파괴·삭제를 허용하며 내용 보존 때문에 크기 변경을 막지 말라고 했다. 또한0점의 긴 가로·세로 선에서만 공간을 넣고 빼지 말고 변경 지점을 무작위로 흩뿌리라고 명시했다. 종전의 wide-boundary·occupied-boundary 보류는 제거한다. 제품 헌법의 비영속성·가변 토러스와 일치하므로 헌법 본문은 수정하지 않는다.

**대안:** 가장자리 증감은 지역을 원점 경계에 몰아넣고 CJK가 성장을 막았다. 무작위 전체 행·열 strip은 위치만 바뀐 긴 직선 경계를 만든다. 모든 셀의 완전 무작위 재배치는 단어 전체를 불필요하게 해체한다. 행마다 다른 가로 삽입/삭제 뒤 열마다 다른 세로 삽입/삭제를 적용하는 격자 변환을 선택했다. 사각형 토러스는 유지하되 인접성·주소의 영속성은 보장하지 않는다.

**분산과 빈칸:** 각 축을최대16개 구간으로 나누고 구간의 위상·선택 위치를 시드 기반 난수로 바꾼다. 구간별 할당으로 한곳에 삽입이 몰리는 것을 피하고, 구간 안에서는 빈 좌표/공백과 글자 사이를 우선한다. 전역의 빈 띠 하나에 모든 변경을 몰아넣는 최적화는 하지 않는다. 확장 시 같은 지점에 여러 칸을 넣을 수 있어2배 성장에서도 모든 칸 사이에 일률적인 선이 생기지 않는다. 축소는 필요한 칸 수를 반드시 제거한다. 최소/최대 실험 크기와 밀도·cooldown은 유지한다.

**문자와 커서:** 남은 문자·작성자·작업 묶음·버전·원래 신선도를 유지한다. 두 칸 문자는 새 head의 오른쪽에 tail을 함께 배치할 여유가 있으면 복구하고, 삭제/충돌하면 전체를 제거한다. 고아 continuation은 만들지 않는다. 삭제된 위치의 커서는 해당 축의 다음 살아남은 위치로 옮긴다. 기존 삭제 tombstone은 크기 변경 때 버린다.

**원자성과 입력:** 전체 새 cells와 크기 meta, 시드·전략·손실량을 담은 topology_events 기록을 한 SQLite 트랜잭션에 저장한다. 커서·메모리 전환은 성공 후 적용한다. epoch를 올려 이전 주소의 쓰기·scavenger 삭제를 거부한다. 모든 연결은 새 시야 snapshot을 받고, 서버 native 문맥과 봇 작성 경로를 비운다. preservesAddresses는false다. 활성 OS 조합 DOM은 종료 전까지 보호하지만 이전 조합의 늦은 확정은 새 좌표에 쓰지 않는다.

**계측과 한계:** seed와 요약만 저장하고 영구 셀별 remap 배열을 추가하지 않는다. resize 처리시간·생존/삭제 셀 수를 계측한다. 동기 전체 재배치는 큰 세계에서 CPU·DB 쓰기 비용이 크며 후속 공간 분할 실험 대상이다. 기존 history가 완전한 epoch별 좌표 타임라인을 제공하는 것은 아니다. 현재 셀의 provenance와 topology event를 남기며 별도 이력 수명 관리 과제는 유지한다. 다음 실험은 분산 정도와 빈칸 우선의 실제 글자 손실량, 사용자 재배치 체감을 함께 측정하는 것이다.

**입력 트랜잭션 검증:** 확정된 쓰기는 먼저 커밋된 뒤 재배치된다. 전송을 지연한 이전 epoch 쓰기는 통째로 거부되고 새 위치에 재생되지 않으며 새 epoch 입력은 정상 반영된다. 과거 native 범위·queued 이동·관성을 무효화한다. 봇의 이미 수행한 단계는 보고하고 나머지는 epoch 경계에서 멈춘다. 저장 실패 시 cells/meta/event와 커서가 함께 롤백된다.

**검사 중 발견한 기존 문제:** 120ms 넘게 늦은 프레임에서 wheel의 남은 입력량까지 버리고 카메라 정착을 생략하던 문제가 재현됐다. fling은 지연 시 중단하되 wheel은 smoothing 시간만 제한하고 명시적으로 받은 이동량은 보존하도록 바꿨다. 숨김·새 탐색·topology 전환은 여전히 취소한다. 지연 프레임에서도 wheel 총량과 최종 정착을 검사했다.

## 2026-11-02 — 신선도 수명, 작성자 색, 간결한 지도

**선택:** 신선도별 배경 대신 글자에 단계별 투명도를 적용하고, 약 1시간에 도달하면 서버의 별도 만료 정책이 5초마다 최대 500개의 글자를 삭제한다. 5초 단위 공유 시간 표식의 불확실성을 고려해 5초를 더 기다린다. 일반 입력과 크기 변경은 기존 단일 writer 순서에 따르며 삭제는 epoch와 셀 version을 확인하고 CJK 쌍을 함께 지운다. 사용자 요청에 따라 별도 scavenger 프로그램과 관리 API는 제거했다. 헌법은 그대로 유지하고 엔진에는 나이 정책을 넣지 않는다.

**대안:** 매 셀 정확한 시각 저장은 저장량이 커 기존 공유 표식을 활용했다. 매번 전체 DB를 재작성하거나 즉시 전부 삭제하면 입력 지연이 커질 수 있어 배치를 제한했다. 단일 프로세스의 메모리 셀 순회는 현 규모의 실험적 선택이며 큰 월드의 스캔 비용, 만료 적체와 history/색상 테이블 보존은 측정 후 개선한다.

**색:** 작성자 색은 익명 세션에 충돌 없이 배정하고 최초 쓰기 때 작성자당 한 번 저장한다. 셀에 색을 반복하지 않고 관측의 version별 색 표로 전한다. 색상 정보가 없는 이전 글은 중립색이며 재접속 시 새 색을 받는다. 색 선택과 지속적인 사용자 정체성은 백로그다.

**UI:** 격자와 경계선, 로고·물음표·좌표·범례·줌 버튼을 제거하고 공유·GPS·연결 상태를 남겼다. 최초 탭 세션에는 3초 로고 후 페이드아웃한다. 커서 정착점은 가로 50%, 세로 43%다. 관측 시야에 추가 여유를 둔다.

**망점:** 격자선 대신 지도 좌표에 고정된 옅은 정사각 간격 점을 그린다. 기본 간격은 가로·세로 모두 26px이고 확대율에 비례한다. 문자 셀(9×26px)과 망점은 별개다.
