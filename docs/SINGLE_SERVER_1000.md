# 단일 서버 1,000명 검증

**검증 진행 중. 공개 상한은 아직 300명이다.** 공유 인코딩·간결한 관측 형식·부분 렌더링은 공개 지도에 반영했다. 신선도 계산의 반복을 줄였으며, 추가 압축과 최종 용량 설정을 비교하고 있다. 단일 Node 서버·SQLite·WebSocket을 유지한다. 제품 헌법과 세계의 수명·밀도·시야·중간 변경 보존 규칙은 바꾸지 않았다.

동일한 생성 부하를 썼지만 전체 행동 예산은 120/초·순간96에서 240/초·순간192로 바뀌었다. 후보는 이동에도 예상 관객 수를 반영하며 최대 5배 상한을 없앴다. 따라서 이 표는 전체 변경의 비교다. 인코딩 효과만 확인하는 대조는 같은 후보 코드에서 기존 형식/새 형식/압축을 바꿔 별도로 실행한다. RSS가 줄었다고 주장하지 않는다.

Node 24.22.3, 4CPU 할당·16GiB 환경에서 서버와 발생기를 별도 프로세스로 실행했다. 작성자 20명은 초당 3회, 산책자 80명은 10초마다 5회 이동하고 900명은 읽는다. 25%가 33×17칸 광장에서 출발한다. 4분의 1은 150×50, 나머지는 52×40 시야다. 세계는 512×256에서 시작하며 초기 글자 6,000개 중 75%가 두 칸 문자다. 입장 중에만 초기 글자 나이를 고정하고, 시작 후에는 실제 시간대로 풍화·삭제·적응·정리가 실행된다. 각 180초 표본에서 150회 접속을 교체했다. 발생기는 ACK를 기다리지 않고 예정 시각에 보낸다. 실행 환경 지문·코드 digest·미처리·실패를 원자료에 남겼다.

관측 순번 공백·역행과 크기 변경 기준 불일치는 두 실행 모두 0이었다. 이 3분 조건에서 실제 확장·축소는 발생하지 않았다. 움직이는 모든 관측자의 내용까지 독립적인 기대열로 전수 대조했다는 뜻은 아니다. 장시간 내용 대조와 별도의 확장·축소·급증 검증을 추가한다. 한도 1,000에서 1,001번째 연결은 503과 Retry-After 5초를 받았다.

## 전송 형식만 바꾼 대조

같은 `a2cd85a`·같은 시계 정렬·같은 240/192 예산에서 모두 18,005개 행동을 승인했다. 프레임 바이트는 서버 소켓에서 계량했으며 TLS·재전송·외부 프록시 바이트는 포함하지 않는다.

새 인코딩은 약 58%의 전송량을 줄였다. 추가 압축의 17% 절감은 입력·관측 지연과 CPU 증가를 동반해 기본 설정에서 제외한다. 평균값을 넘어 모든 프레임이 같은 비율로 개선됐다는 의미는 아니다.

고정 시야의 1,000명 별도 시험에서는 72개 쓰기에 대한 72,000개 관측을 모두 받았다. 자기/타인 쓰기 누락·시야 밖 쓰기·순번 공백·접속 이탈·거절·남은 대기가 0이었다. 같은 칸의 중간 덮어쓰기도 대조했다. 이 시험은 실제 시계 장기 검증과 구분한다.

## 밀집 부하의 한계와 보호

전원 광장·1,000명·135초에서 보호 수정 전에는 입력 확인 p95가 20.1초, 연결 이탈이 924건이었다. 수정 후보는 13,496개 중 3,740개를 승인하고 9,756개에 429를 반환했다. 연결 이탈과 배출 후 대기는 0, 확인 p95 118ms·다른 참가자 수신 226ms·전송 준비 104ms였다. 재입장 p95는 5.45초였다.

**이 조건은 정상 처리량 검증에 합산하지 않는다.** 승인된 기록을 버리지 않고 변경 전에 행동을 거절하는 보호 시험이다. 모두 같은 장소에서 같은 속도로 활동하는 1,000명을 무제한 지원한다는 결과가 아니다. 이 보호의 후보 표본은 생성자 기본값 변경 전에 실행했지만, 명시적으로 240/192를 전달했다. 해당 기본값 차이만 되돌린 소스 digest가 원자료와 일치함을 확인했다.

1,000개 가상 커서와 560개 글자를 표시하는 별도 브라우저 fixture에서 원격 갱신의 그리기 p95는 11.4→4.8ms, 스크롤 중에는 11.0→6.2ms였다. 정지 화면의 글자·이름표 그리기 호출 중앙값은 1,559→58회였다. 이 가상 커서는 서버 동접 증거가 아니다. 이동 최대값 한 번은 22.4→31.7ms로 더 길어졌으므로 모든 프레임의 개선을 주장하지 않는다.

## 남은 판정

1,000명 정상 혼합 부하의 판정은 미확인·비계획 종료·관측 순번 공백·기준 불일치·내용 대조 차이 0, 예정 입력→ACK p95 150ms, 서버 전송 준비 p95 100ms, 다른 독자 디코딩 p95 200ms, 재입장 p95 1초, 만료 나이 p95 200초를 사용한다. 독자 200ms는 [이번 최적화 실험안](OPTIMIZATION_OPTIONS.md)의 기준이며 이전 300명 공개판의 150ms 목표와 구분한다. 구간별 꼬리 지연·재입장 p99·저장량과 최악의 밀집 거절률도 별도로 공개한다. 좌석 수를 늘려도 승인하지 못한 행동을 성공 건수로 계산하지 않는다.

- 최종 설정의 실제 시계 1시간, 접속 교체, 입력 중단 뒤 풍화·삭제·축소·이력 회수.
- 1,000명 밀집 급증 이후 회복. 공개 300명의 확장·축소 중 입력 회귀는 위 시험에서 확인했다.
- 공개 지도의 최종 버전·외부 브라우저·실측 기반 원가와 운영 상한.
