### 지연과 렌더링을 구분해 측정

300ms 서버 수신 지연을 준 동일 Chromium 실험에서 영문 input→최초 Canvas paint 시작은 **318.7→4.5ms**, 한글 확정은 **319.1→7.0ms**였다. 기존 화면은 지도만 약 3~4ms에 먼저 이동하고 글은 서버 응답까지 비었다. 이제 `localCells`를 즉시 그린 뒤 서버의 최신 확정 상태와 남은 작업을 합치므로 그 빈 구간이 없다. 이 수치는 모니터 scan-out 완료나 실제 모바일 OS 키보드 지연이 아니다.

카메라 애니메이션을 처음 붙였을 때 4,760글자 밀집 화면에서 그리기 중앙값 16.3ms, 프레임 간격 중앙값 28.7ms를 관측했다. 중복 RAF를 제거하고 Unicode 폭 메모·텍스트 패스의 그리기 설정을 묶은 최종 구현에서는 각각 **9.7ms, 19.4ms**였다. 저밀도 화면은 그리기 중앙값 2.9ms, 프레임 간격 16.6ms였다. 단일 환경의 실측이며 동시 부하 영향도 있어 모든 화면에서 60fps를 보장하는 결과는 아니다.

별도 대안 실험의 glyph bitmap 캐시는 원래 10.4~12.1ms였던 화면을 32.9~33.2ms로 늦춰 기각했다. 같은 `fillText`를 유지하는 단순 상태 묶기는 7.0~7.6ms였다. 이 대안 비교 수치는 위 최종 앱 측정과 구분한다. DPR2의 상태 묶기 효과는 실행 간 변동이 커 확정하지 않았다.

근거: `artifacts/typing-latency-baseline.json`, `typing-latency-final.json`, `typing-latency-results.json`, `glyph-batch-prototype-results.json`. 실행 산출물은 git에서 제외한다.

### 발견한 실패와 수정

- 실제 contenteditable의 조합 범위만 표시한다. native DOM·selection을 바꾸지 않고 `Range`와 CSS clip/transform을 사용한다. Canvas에 조합 글을 한 번 더 그리지 않는다. 브라우저 font box와 Canvas baseline을 맞췄다.
- `overflow:hidden` 컨테이너는 긴 native 조합 때 브라우저가 내부를 최대 8,800px 자동 스크롤할 수 있었다. `window.scrollX/Y`는 0이어서 이것만 확인하면 놓친다. 지도 컨테이너를 `overflow:clip`으로 바꾸고 app/viewport scroll offset과 실제 canvas 원점을 검사했다.
- 가상 키보드로 보이는 높이가 줄 때 기존 순간 이동 방지 로직이 오히려 즉시 중앙으로 이동시켰다. viewport 변화에서는 필요한 경우에만 가장 가까운 보이는 경계까지 보정하고 나머지는 부드럽게 중앙으로 이동한다.
- typing 시점 이동 중 지도를 잡아도 카메라가 계속 움직여 100ms 동안 약 31px 더 이동했고, 첫 10px 드래그가 약 22px 이동했다. 잡는 순간 표시 위치를 멈추고 드래그의 시작 오프셋을 보존한 뒤 놓을 때 중심으로 돌아오도록 고쳤다. 회귀에서 잡고 있는 동안 0.01px 이내 고정, 첫 드래그 정확히 10px를 확인했다.
- IME가 관성을 중단한 뒤 fractional 이동량 때문에 커서가 중심으로 복귀하지 않는 경우를 발견했다. 입력·도움말·연결 상태 등 중단 경계에서 남은 이동량을 정리한다.
- 첫 입력의 일반 RAF와 카메라 RAF가 같은 프레임에 지도를 두 번 그릴 수 있었다. 그리기를 합친 뒤 실제 23프레임에서 23회, 프레임당 최대 한 번을 확인했다.

키보드 전환 검사는 Chromium의 `visualViewport` 크기·offset을 모의 변경했다. 폰트·zoom이 유지되고, 중간 프레임에서도 Canvas 글·native 조합·커서가 같은 세계 주소에 붙는지 확인했다. 실제 OS 키보드 창·Safari·Firefox 검증은 아니다. 비선형 공간 문맥을 가로지르는 다중 행 조합 미리보기와 아주 빽빽한 모바일 화면의 성능은 남은 실험이다. 제품 헌법은 변경하지 않았다.

이번 검증에서 찾고 고친 실패:

- Chromium 154의 `contenteditable="plaintext-only"`는 `beforeinput.getTargetRanges()`가 비어 있었다. `contenteditable="true"`와 명시적 plain-text 정책을 선택했다. Blink 소스에서도 이 조건을 확인했다.
- 붙여넣은 줄바꿈을 Backspace로 되돌릴 때 빈 write가 전송되어 세계 버전이 증가했다. 문자 변경 없이 presence만 이동하도록 고쳤다.
- 현재 주소로 다시 탐색하면 공간 문맥만 비우고 native DOM을 남겨 다음 입력이 거절됐다. 두 문맥의 초기화 경계를 일치시켰다.
- Ctrl·Alt·Meta 탐색과 PageUp/Down이 숨은 caret만 움직일 수 있었다. 조합 중 후보 탐색은 그대로 두고, 조합 밖의 미정의 탐색은 안내와 함께 차단한다.
- 여러 행 붙여넣기 후 이전 행을 재변환하면 미리보기를 현재 행에 그렸다. 실제 범위의 x/y 주소에 그리도록 수정하고 canvas 좌표·확정 결과·다음 행 보존을 검사했다.

Sarasa Fixed K Regular 1.0.43은 실제 18px 렌더링에서 `i/W/M/é/Ω/—/ｶ`가 9px, `한/글/中/文/あ/ア/Ａ`가 18px였다. 지도는 9×26px 기본 격자를 사용한다. 글자를 `fillText` 최대 폭으로 압축하지 않는다. 데스크톱·모바일·조합·도움말 스크린샷을 저장하고 직접 열어 확인했다. 글꼴 파일·문자 범위·라이선스 근거는 [CJK_FONT.md](research/CJK_FONT.md)에 있다.

**검증의 한계:** 브라우저 실행은 Chromium이고, IME는 실제 Chromium CDP 입력과 명시적인 표준 이벤트 순서 변형으로 검사했다. 실제 한국어·일본어·중국어 OS 키보드와 후보창, iOS/Android, Safari/Firefox를 직접 실행한 결과는 아니다. motion 테스트는 앞선 두 실행에서 타이밍 실패가 있었고 최종 단독 실행은 10/10 통과했다. 원인을 해결했다고 주장하지 않으며 실패 시 포인터 시간 기록을 남기도록 했다.

## 실제 검증한 동작

- 두 독립 클라이언트가 같은 셀을 경쟁해서 써도 서버 순서와 최종 상태가 일치한다. overwrite/delete는 옆 셀의 글·버전을 바꾸지 않는다.
- 같은 입력 작업을 재전송해도 과거 글자가 되살아나지 않는다. 재접속은 현재 snapshot을 받으며 자동으로 과거 입력을 재생하지 않는다.
- 음수 좌표, 오른쪽/아래 경계, 한 행보다 긴 붙여넣기에서 torus overwrite가 유지된다.
- 한글 자모 조합, combining accent, 국기, ZWJ 가족 이모지를 grapheme으로 다룬다. Chromium CDP의 native IME 경로에서 `ㅎ → 하 → 한` preedit는 전송하지 않고 최종 `한`만 한 칸에 기록했다.
- stale epoch 입력을 거절하고 새 지도를 받는다. 같은 오래된 요청 다발에는 스냅샷을 중복 전송하지 않는다.
- density hysteresis에 따른 확장·축소, 점유된 셀/커서가 있는 band 축소 보류, SQLite 재시작 복구를 검증했다.
- 실제 별도 scavenger 프로세스가 오래된 4칸을 지우고 현재 글을 남겼다. 삭제 패치가 실시간 도착했다. 오래된 evidence로 새 버전을 지울 수 없다.
- GPS의 반대 경도·극점 경계, 허용/거절 시의 진입, GPS 버튼이 갱신된 위치를 다시 읽는 동작을 확인했다. 위치는 브라우저에 모의 제공했으며 실제 GPS 센서는 사용하지 않았다.
- 스크롤/드래그/줌에서 커서가 viewport 안에 남는다. 모바일 터치 선택·입력·드래그, 390×844 및 390×520 화면에 가로 overflow가 없다.
- Chromium pageerror는 없었다. 연결 중단 시 입력 비활성화, 재접속 최신 세계 복구를 확인했다.

렌더링 결과 `artifacts/desktop.png`, `artifacts/mobile.png`, `artifacts/mobile-keyboard-height.png`를 생성하고 직접 열어 확인했다. artifacts는 재생성 가능하며 git에 포함하지 않는다.

독립 검토에서는 재접속 후 `{7,8}` 위치 유지 및 wheel 이벤트 220회 연속 후 연결 유지도 브라우저에서 확인했다. 이 두 점검은 별도의 수동 스크립트 실행이므로 자동 테스트 39개 수에 더하지 않는다.

## 발견하고 고친 실패

1. 탭을 브라우저는 1칸, 서버는 4칸으로 계산했다 → shared writePlan 재사용.
2. 같은 페이지에서 hash만 바뀌면 링크 좌표로 가지 않았다 → hashchange 이동 처리.
3. GPS 복귀가 60초 캐시를 재사용했다 → 명시적 복귀 요청은 maximumAge=0.
4. 재접속 때 이전 위치를 잃었다 → snapshot 수신 후 이전 cursor를 새 epoch에 복원.
5. 빠른 pan의 fractional 이벤트마다 presence를 전송했다 → 40ms 합치기와 동일 위치 생략.
6. stale 요청마다 snapshot을 보냈다 → 연결별 마지막 전송 epoch를 기록.
7. snapshot/이동 후 늦은 조합 완료가 새 위치에 입력될 수 있었다 → active composition 및 취소 상태 검사와 companion input 억제.
8. 빈 textarea에서 mobile Backspace가 input을 만들지 않을 수 있었다 → cancellable beforeinput 삭제를 처리.

## 아직 검증하지 않은 것

- 실제 Android/iOS 한국어 키보드, Safari/Firefox, 모바일 OS 키보드가 만드는 visualViewport 변화. 짧은 viewport 에뮬레이션은 실제 키보드 검증이 아니다.
- 장시간 부하, 200/800ms 지연 비교, 대규모 history·셀 수, 프로세스 crash/fsync 전원 손실, 다중 서버.
- 전체 격자를 읽는 보조기술 접근성. 현재 Canvas 안내/라벨과 native textarea를 제공하지만 읽기 경험은 부족하다.
- abuse 대응, 인증/권한, history 보존 기한과 compaction. 이 최초 검증 이후 Railway HTTPS 배포와 실제 공개 주소의 두 브라우저 동기화는 [배포 기록](DEPLOYMENT.md)에서 추가 검증했다.
- 크기 변경에 대한 사용자 인지 실험. 현재 확장은 경계 문장 인접성을 유지하지 못하며, GPS 장소/좌표 링크는 resize에 안정적이지 않다.

다음 실험: 같은 경계 문장·커서·GPS anchor fixture에 정수 torus와 immutable 행/열 ID의 빈 strip 변환을 적용하고, 글자 충돌, 인접성 단절, 사용자 커서 이동 거리, GPS 재방문 거리를 비교한다.
