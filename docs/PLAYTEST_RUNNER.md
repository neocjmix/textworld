# 혼자 들어가는 다중 사용자 시험

초기 공개 시험에는 [300명 시나리오](../experiments/playtest/release-300.json)를 사용했다. 운영자 봇은 최대 298명으로 두고 외부 브라우저 두 대가 같은 광장에서 글을 주고받았다. 실행은 440초, 2,100봇분, 수신 1,024MiB, 입장 850회 중 먼저 도달한 제한에서 끝난다. [측정과 운영 판정](INITIAL_RELEASE.md)

휴대폰이나 컴퓨터에서 공개 체험 위치를 열고 운영자에게 **“테스트 시작”**이라고 말한다. 같은 프로덕션 지도에서 직접 글을 쓰고 참여자의 커서를 따라갈 수 있다. 체험 위치는 현재 글쓴이 봇의 좌표로 이동하고, 대기 중일 때는 세계 중앙으로 이동한다. 방문·새로고침은 위치만 연다. [프로덕션 체험 위치](https://textworld-production-987c.up.railway.app/playtest)

### 운영자 실행

Railway에 인증한 운영자가 아래 명령으로 상태를 확인한다. `status`는 읽기 전용이다.

```sh
railway run --no-local --project c702f64c-3e82-47e8-9945-e0540b1b5b2b \
  --environment dcf0285c-151d-4a4a-ac7a-37efab3fcb0d --service 99c29cc7-7ab4-4939-85d3-48044329b4e7 \
  -- node experiments/playtest/control.mjs status
```

사용자가 시작을 요청하면 끝의 `status`를 `start`로 바꾼다. 실행 ID와 체험 링크가 출력된다. 다른 구성을 쓰려면 `start UUID scenario.json`을 사용한다. 요청 결과가 불확실하면 같은 ID로 조회하거나 재요청한다. `status ID`, `set ID 6 4 22 overwrite`, `mark ID 키보드 지연`, `stop ID`가 같은 실행을 제어한다. 한 번에 한 실행만 허용한다. 중복 시작 또는 배포 뒤 같은 ID를 다시 보내도 이전 실행 상태를 반환한다.

참가자는 기존 프로덕션 서버에 정상 WebSocket 입력을 보낸다. 운영자 명령은 전용 비밀값으로 인증하고, 내부 참가 연결은 한 실행 동안 열린 루프백 포트에서만 받는다. 각 참가자와 모의 네트워크에 기존 제한이 적용된다. 시작·목표 변경·체감 메모·측정값·종료 결과는 볼륨의 `/data/playtests/<ID>/`에 남는다. 진행 중 프로세스가 교체되면 새 버전은 대기로 시작한다. 완료 기록을 쓰기 전에 프로세스가 강제 종료된 실행은 ID 조회 시 `interrupted`로 나타난다. 세계의 글과 사용자 접속은 일반 제품 규칙을 따른다.

### 개발용 로컬 재현

아래는 브라우저 자동 시험과 재현에 쓰는 선택 사항이다. Node.js 24 이상에서 실행하면 임시 SQLite를 사용하는 로컬 지도가 열린다.

```sh
npm ci
npm run playtest
```

휴대폰으로 보려면 `npm run playtest -- --lan`을 실행하고 같은 Wi-Fi에서 **같은 네트워크** 링크를 연다. 이 옵션은 시험 지도 포트를 모든 네트워크 인터페이스에 연다. 기본값은 이 컴퓨터에서만 접속할 수 있는 루프백이다. 포트를 고정하려면 `--port 3001`을 더한다. 로컬 Wi-Fi의 HTTP에서도 키보드로 지도에 입력할 수 있고, GPS와 클립보드에는 브라우저의 보안 컨텍스트 제약이 적용된다.

## 6분 5초 동안 일어나는 일

| 구간 | 시간 | 글쓴이 / 산책자 / 독자 목표 | 지도에서 볼 것 |
| --- | ---: | --- | --- |
| 입장 | 15초 | 2 / 2 / 2 | 옆줄에 쓰고 상대 커서를 따라간다 |
| 혼잡 | 70초 | 12 / 5 / 7 | 타이핑과 스크롤을 해 보고, 새 칸이 늘어날 때 내 위치를 확인한다 |
| 퇴장 | 15초 | 2 / 1 / 3 | 주변 커서가 줄어도 기존 글은 남는다 |
| 만료와 축소 | 265초 | 0 / 0 / 0 | 쓰기를 잠시 멈추고 글이 옅어져 사라진 뒤 세계가 작아지는 것을 본다 |

봇은 매번 24~48초의 수명을 배정받는다. 자리가 남으면 다음 참가자가 들어오고, 목표를 내리면 초과한 참가자부터 떠난다. 입장은 350ms당 최대 한 명이다. 글쓴이는 짧은 한글 구절을 이어 쓰거나 같은 칸을 반복해서 덮는다. 산책자는 작은 보폭으로 움직이고 독자는 자리를 잡고 주변 변경을 받는다. 세계 크기는 실제 점유 밀도에 따라 변한다. 독자만 늘리거나 계속 같은 자리를 덮는 시험에서는 확장이 일어나지 않을 수도 있다. 기본 마지막 구간에는 3분 만료와 저밀도 유지 시간을 모두 포함했다.

글쓴이는 확정된 글자 한 개씩 보낸다. 단어 안에서는 짧게, 공백과 문장 끝에서는 길게 쉬며 각자 다음 행동 시각을 정한다. 시나리오의 `jitterRatio`는 기본 0.3이며 0~0.6 사이에서 조절한다. 기본값에서는 각 행동의 기본 휴식에 ±30%, 개인의 평균 속도에 ±15% 편차를 준다. 입장 간격은 350~560ms이고 목표 감소로 인한 퇴장은 750ms 안에 흩어진다. 서버가 429를 반환하면 지정한 대기 시간을 채우고 양의 지터를 더한다. 수명은 지정한 범위 안에서 뽑고 예산·마감·중지에는 지터를 적용하지 않는다. 실행 결과의 `writtenGraphemes`는 공백을 포함해 확인받은 글자 수이고, `typingGapP50Ms`와 `typingGapP95Ms`는 같은 봇의 연속 글자 송신 사이 간격이다.

## 체감과 수치 함께 기록하기

아래는 로컬 터미널 명령이다. 프로덕션에서는 위의 운영자 명령에 실행 ID를 지정한다. 인원과 패턴 변경은 다음 구간이 시작될 때까지 적용된다.

| 입력 | 동작 |
| --- | --- |
| `set 6 4 22` | 글쓴이 6명, 산책자 4명, 독자 22명을 목표로 조정 |
| `set 6 4 22 overwrite` | 같은 인원으로 제자리 덮어쓰기를 반복. `new-cells`는 새 칸에 이어 쓰기 |
| `set 0 0 0` | 봇을 모두 퇴장시킨 뒤 지도에서 만료 관찰 |
| `status` | 역할별 실제 인원, 세계 크기·점유 칸, 현재 글쓴이 근처의 링크 확인 |
| `mark 키보드를 열 때 커서가 밀림` | 그 시각의 세계·인원·측정값에 메모 추가 |
| `stop` 또는 Ctrl+C | 봇과 월드를 함께 종료하고 결과 저장 |

로컬 재현에서는 `artifacts/playtest/<실행 폴더>/events.jsonl`에 버전·설정·시작 시드와 구간 전환, 수동 변경, 메모, 표본, 종료 사유를 남긴다. 표본에는 실제 역할별 인원, 누적 입퇴장·거절·미확인 입력, 누적 ACK p95, 봇 수신 바이트, 세계 크기와 점유 칸이 있다. 세계 크기가 바뀌면 추가 표본을 남긴다. `metrics.sqlite`에는 기존 서버의 CPU·메모리·세계·분당 전송량과 접속한 브라우저가 보고한 그리기·입력 지연을 보존한다. 글 내용은 집계 파일에 수집하지 않는다. `mark`의 메모는 입력한 그대로 저장한다. 종료 시 임시 세계 DB를 지운다.

화면의 지연을 평가할 때는 본인 입력과 다른 브라우저에 보이는 순간을 함께 본다. 봇은 입력 하나의 응답을 받은 다음 행동하고, 느려져도 밀린 행동을 몰아서 보내지 않는다. ACK 지연은 상대 화면의 표시 지연과 측정 지점이 다르다. 일정한 속도로 계속 입력을 제공하며 포화점이나 누락을 검증할 때는 [별도 부하 시험](SCALING_VALIDATION.md)을 사용한다.

## 시간과 비용

프로덕션은 기존 Railway 인스턴스에서 봇을 실행한다. 로컬 재현에는 Railway 비용이 들지 않는다. 두 방식 모두 모델 호출을 사용하지 않는다. 기본 시나리오의 혼잡 목표는 24명이고, 실행 예산은 **누적 참가 시간 65봇·분, 봇 수신 384MiB, 입장 시도 150회**다. 10명이 1분 머물면 10봇·분이다. 벽시계 마감과 세 자원 예산 중 먼저 닿는 조건이 실행을 끝낸다. 인원 조절로 마감이나 예산을 늘릴 수 없다. 시작·종료에는 각각 최대 15초·약 4초의 별도 대기가 있고, 이미 전송 중인 데이터와 닫히는 연결 때문에 최종 합계에 소폭 차이가 날 수 있다.

[기본 시나리오](../experiments/playtest/wave.json)를 복사해 `lifetimeSeconds`, `budget`, `phases`를 바꾼 뒤 `npm run playtest -- --scenario my-wave.json`으로 실행한다. 구간마다 초 단위 길이, 역할별 수, `writing`과 `actionIntervalMs`를 지정할 수 있다. 한 번에 **최대 300명, 총 1시간**이다. 시드는 봇의 선택을 재현하는 데 쓰고, 운영체제 스케줄링과 서버 응답 시간은 매번 달라진다.

로컬 재현에서 봇의 트래픽은 임시 월드의 전용 루프백 포트로 간다. 이 포트 안에서 가상의 여러 접속 네트워크를 배정하고 서버의 참여자·네트워크별 예산을 그대로 적용한다. 사람은 일반 지도 포트로 접속하며 같은 접속 주소의 8세션 한도가 적용된다. 메모와 제어 명령은 실행 터미널에서만 받는다.

### 실행 한 번의 비용 확인

운영자 명령 끝에 `cost 실행ID`를 넣으면 실행 중의 누계나 종료 결과를 달러로 확인할 수 있다. `status 실행ID`의 `cost`와 볼륨의 `result.json`에는 원 단위의 사용량, 적용 단가와 계산 결과를 함께 보관한다. 구간 전환과 주기적 표본에도 누계가 남아서 두 표본을 빼면 원하는 구간을 비교할 수 있다. 계측 도입 전에 끝난 실행에는 비용 표본이 없다.

| 항목 | 측정과 해석 |
| --- | --- |
| CPU와 메모리 | 서비스 프로세스 전체의 CPU 코어·초와 약 1초마다 측정한 RSS의 GiB·분. 러너, 평소 서버 작업, 동시에 들어온 사람이 모두 포함된다. |
| 볼륨 | Railway가 제공하는 마운트의 사용량을 시간에 따라 적분한 GiB·분. 마운트를 읽을 수 없는 구간이 있으면 미측정으로 표시하고 소계에는 측정된 항목만 넣는다. |
| 공개 송신 | 공개 HTTP 응답 본문과 공개 WebSocket의 송신 데이터 바이트. 같은 인스턴스의 전용 봇 연결은 집계에서 제외한다. 프록시·TLS·재전송은 플랫폼에서 별도로 계량한다. |
| 비교용 값 | 공백을 포함한 확인 글자 1,000개당 추정 소계. 봇 수신 바이트가 모두 인터넷으로 나갔다고 가정한 송신료(`hypotheticalBotEgressUsd`)도 소계와 별도로 보관한다. |

2026-11-26 컨테이너 단가를 적용한다. CPU는 코어·분당 0.000463달러, 메모리는 GiB·분당 0.000231달러, 볼륨은 GiB·분당 0.000003472222222달러, 외부 송신은 GiB당 0.05달러로 계산한다. 1GiB는 2³⁰바이트다. 소계는 해당 시간에 서비스가 쓴 자원의 추정치다. 봇 때문에 추가된 비용을 추정하려면 같은 시간 길이와 비슷한 접속자 수의 봇 0명 구간을 함께 측정한다. 월 기본료, 크레딧, 빌드, 백업과 최종 청구액은 Railway 사용 내역에서 확인한다. [Railway 요금표](https://docs.railway.com/pricing/plans#resource-usage-pricing)

### 한 글자 쓰기와 지터 검증

2026-11-26에 로컬에서 두 버전의 정상 WebSocket 경로를 비교했다. 시드 17, 글쓴이 한 명, 독립 Chromium 관찰자 한 명으로 각각 31초 동안 실행했다. 공백은 전송한 글자 수에 포함했다. 화면 간격은 새 글자가 보이는 캔버스 그리기 사이에서 쟀다.

| 관측값 | 세 글자씩 쓰던 버전 | 한 글자씩 쓰는 버전 |
| --- | ---: | ---: |
| 쓴 글자 | 90자 | 98자 |
| 한 번에 보낸 글자 | 3자 | 1자 |
| 화면에 새 글자가 뜨는 간격 중앙값 | 1,000ms | 239ms |
| 화면 간격 95백분위 | 1,200ms | 1,106ms |

새 버전에서 글쓴이가 한글 음절 뒤에 쉰 시간은 중앙값 197ms, 공백 뒤에는 513ms였다. 글쓴이 6명·산책자 2명·독자 1명의 별도 실행에서 입장은 360~514ms 간격이었고 9명의 퇴장은 516ms에 걸쳐 일어났다. 196건 모두 확인 응답을 받았고, 100ms를 10ms씩 나눈 열 구간에 각각 13~28건씩 도착했다.

31초 실행에서 비용 계측은 CPU 1.24코어·초, 메모리 0.1074GiB·분, 공개 HTTP 56,014바이트, 공개 WebSocket 75,422바이트를 기록했다. 로컬에는 Railway 볼륨이 없어 해당 항목은 미측정이었다. 이 표본에 Railway 단가를 적용한 예시 소계는 0.00004050달러다. 프로덕션에서 관측한 수치는 해당 실행의 `cost 실행ID`로 조회한다.

## 2026-11-26 실행 기록

기본 시나리오 한 번에 62명이 차례로 입장하고 최대 24명이 함께 머물렀다. 40명은 수명을 다했고 22명은 인원 목표가 내려갈 때 퇴장했다. 봇 입력 1,205건 모두 ACK를 받았다. 거절·미확인 입력은 0건, 봇 수신량은 62,517,114바이트였다. 데스크톱 Chromium에서 쓴 한글을 모바일 크기의 독립 Chromium 화면에서 읽었고, 같은 화면에 주변 참가자 14명이 보였다. 실제 휴대폰 키보드와 외부 인터넷 지연은 후속 검증 대상이다.
