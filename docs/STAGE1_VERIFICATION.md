# 단일 서버 1단계 검증 — 2026-11-18

기준 구현은 `2eec724`, Railway 시험 대상은 `4b71230`이다. 예상 피크의 시험값으로 **같은 지역에서 32명이 각자 초당 한 글자**를 입력하는 경우, 1.5배 시험값으로 48명을 선택했다. 실제 운영 피크는 아직 관측하지 못했다.

## 시험 방법

서버와 부하 생성기는 별도 Node.js 프로세스에서 실행한다. 참가자는 모두 실제 WebSocket으로 접속해 브라우저와 같은 시야·입력 제한을 적용받는다. 합성 세계의 초기 크기는 512×256, 시야는 160×48이다. 12초 단기 시험은 기존 보고서와 같은 고정 세계 시계와 입력 도착률을 사용한다. 장기 시험에서는 시간을 실제로 흘려 만료·신선도 변화·저장 정리·자동 크기 변경을 함께 실행한다.

입력 ACK, 서버 입력 수신부터 변경 전송 준비까지, 다른 참가자가 해당 셀 버전을 디코딩할 때까지의 p95를 따로 계산한다. 제공한 입력을 모두 처리했는지, 전송을 마친 뒤에도 대기가 남았는지, 관측 순번에 공백이 있는지도 검사한다. 단기 시험에서는 보이는 쓰기 버전과 실제 수신 버전을 비교하고, 분리된 시야에서는 보이면 안 되는 버전도 확인한다. 브라우저 렌더링과 IME는 실제 Chromium으로 따로 시험한다.

아래 명령으로 같은 조건의 집중 부하를 재현할 수 있다.

```sh
CAPACITY_DURATION_MS=12000 \
CAPACITY_CASES='[{"peers":32,"active":32,"rate":1,"layout":"uniform","action":"type","batch":true}]' \
node experiments/capacity.mjs
```

한 시간 시험은 위 사례에 `"liveClock":true`를 추가하고 `CAPACITY_DURATION_MS=3600000`을 지정한다. 부하 생성기의 소켓은 루프백 주소에만 접속하며 각 실행은 별도 임시 SQLite 파일을 사용한다. [시험 코드](../experiments/capacity.mjs)

## 크기 변경

57,344칸이 점유된 896×448 세계의 자동 확장 3회에서 셀 손실은 0이었다. 커서·세계 상태를 확정하는 마지막 전환은 1.83~2.65ms, 5ms 간격 타이머가 관측한 최대 간격은 52~89ms였다. 작업의 처음부터 이전 테이블 정리까지는 2.23~3.42초가 걸렸다. 이 수치는 접속자가 없는 로컬 SQLite 실험이다. 이전 동기 구현에서 같은 규모의 작업은 이벤트 루프를 283~433ms 점유했다. ## 단기 부하

아래는 4코어 CPU 할당량을 공유하는 로컬 Xeon 환경에서 12초간 입력한 단일 표본이다. 생성기와 서버는 별도 프로세스였고, 호스트에서 다른 검증도 진행 중이었다. 각 행에서 예정된 입력의 ACK를 모두 받았고, 입력 제공이 끝난 시점의 미처리량은 0이었다. 관측 순번 공백, 잘못된 지역에 전달된 쓰기, 누락된 공개 변경, 429 및 연결 종료도 0이었다.

32명 집중 입력의 시야 변경은 12,288건 모두 도착했다. 같은 호스트에서 이전 코드를 실행했을 때는 입력 제공 종료 시 267건이 밀렸고 ACK p95는 31.4초, 수신량은 64.69MB였다. 종전 보고서의 6~7초는 다른 CPU에서 측정했다. 처리시간 개선 비율은 호스트 부하에 따라 달라진다. [같은 호스트의 이전 구현](measurements/stage1-local-base-2026-11-18.json) · [변경 후](measurements/stage1-local-release-2026-11-18.json)

조밀한 시야의 첫 혼합 시험은 내부 p95 100ms 목표를 넘겼다. 같은 커밋과 입력으로 두 번 더 실행한 결과는 67.6ms와 75.3ms였고, 세 실행 모두 각 3,072건을 전달했다. 같은 호스트에서 다른 시험이 겹친 첫 표본도 결과에 포함한다. [반복 측정](measurements/stage1-local-dense-repeats-2026-11-18.json)

## 회귀 검사

Chromium에서 데스크톱·모바일 화면, CJK 폭, 입력 예측, 동시 덮어쓰기, 한글 조합 중 크기 변경, 신선도 표시를 확인했다. ACK가 먼저 와도 작성자의 예측이 유지되고 시야 순번 공백에 대한 snapshot 요청이 429로 밀려도 조합을 보존한다. 시야·전송 단위 시험은 중간 글자·커서 순서, 구형 클라이언트, 바이트 상한, 끊어진 연결의 복구를 포함한다.

화면 움직임 검사에는 두 가지 기존 실패가 남았다. 키보드 개폐 애니메이션의 중간 프레임 검사와 이동 중 커서의 0.1px 정렬 검사다. 변경 전 main에서도 같은 검사 항목의 실패를 재현했다. 실제 휴대폰 OS 키보드는 이 환경에서 검증하지 않았다.

## 저장 수명

가상 세계 시계로 한 시간을 진행하며 파일 SQLite에 초당 32건과 48건을 각각 확정했다. 115,200건과 172,800건을 기록했다. 두 경우 모두 10분부터 60분까지 5분 간격의 모든 표본에서 history는 각각 25,308행과 37,960행, 중복 방지 기록은 각각 9,560행과 14,280행으로 유지됐다. 종료 시 DB의 할당 크기는 9.49MiB와 14.01MiB였다. 닫고 다시 열었을 때 모든 셀 필드와 세계 메타데이터가 일치했다. 이 시험은 저장 수명 검증이며 지연·네트워크 수치는 실제 시계 시험에서 측정한다.
