# 공간 모델 실험 — 2026-11-02

이 문서는 구현 가설과 반례를 기록한다. 제품 헌법을 변경하거나 새로운 제품 요구사항을 확정하지 않는다. 실행: `node experiments/topology.mjs`.

## 크기와 셀의 정체성은 서로 다른 문제

| 후보 | 셀 정체성과 성장 | 장점 | 가장 먼저 깨지는 가정 |
| --- | --- | --- | --- |
| 희소 정수 격자 + 가변 modulo | `(x,y)`가 주소이자 정체성, 폭·높이만 변경 | 즉시 주소 지정, 일반 셀의 글자 간격 보존, 구현·검증이 간단 | 확장에서 기존 경계 인접성이 사라지고, 축소에서 주소가 충돌한다 |
| 정규화 좌표의 연속장 | `(u,v)`를 영구 저장하고 화면에서 해상도에 맞춰 양자화 | GPS와 세계 상대 위치가 안정적, 해상도 독립적인 저장 | 해상도 변화가 글자를 벌리거나 같은 셀로 합친다. 충돌 해소 뒤 원래 글자를 복구할 근거도 필요하다 |
| 순서가 있는 행/열 ID | 셀은 `(rowId,colId)`이고 주소는 현재 순서에서 계산 | 빈 strip을 삽입·제거하며 기존 글자와 출처를 유지할 수 있다 | 위치 주소가 바뀌고, 빈 행·열이 없으면 축소가 막힌다. GPS를 ID에 연결하는 별도 anchor가 필요하다 |
| 지리 atlas의 적응적 분할 | 지리 영역을 계층적으로 분할하고 leaf에 문자 저장 | 지역 혼잡에만 해상도를 추가하고 GPS 연결 유지 | 서로 다른 셀 크기와 이웃 수를 동일한 2D 문자 격자로 표시할 방법이 미정이다 |
| 고정된 거대 torus + 활성 영역 변화 | 실제 topology는 고정, 활성 창만 늘이고 줄임 | 좌표·GPS·기존 문자 모두 안정적 | 세계 자체의 확장·축소를 활성 영역으로 바꿔 해석할 우려. 제품 헌법 4번의 구현이라고 간주하지 않는다 |

정수 좌표와 서버 순서는 **초기 실험 선택**으로 유용하다. 이를 영구 모델로 확정하려면 경계의 글과 사용자들이 성장·축소를 실제로 경험하는 실험이 필요하다. 셀별 CRDT를 붙여도 위 공간 문제는 해결되지 않는다.

## 실행한 반례

폭 32의 한 행에 길이 8인 글 두 개를 놓았다. 하나는 `28,29,30,31,0,1,2,3`으로 경계를 가로지르고, 다른 하나는 `4..11`에 있다. `12..19`는 비어 있다. 각 행은 16개 문자의 변환 결과다.

| 변환 | 충돌 문자 수 | 끊긴 연속 문자쌍 | 주소가 바뀐 문자 수 |
| --- | ---: | ---: | ---: |
| 정수 modulo, 32→40 | 0 | 1 | 0 |
| 정규화 remap, 32→40 | 0 | 2 | 12 |
| 빈 strip 삽입, 32→40 | 0 | 0 | 4 |
| 정수 modulo, 32→24 | 4 | 1 | 4 |
| 정규화 remap, 32→24 | 4 | 4 | 15 |
| 빈 strip 제거, 32→24 | 0 | 0 | 4 |

이 결과는 strip 모델에 유리한 의도적 작은 반례이며 처리량 벤치마크가 아니다. 모든 열에 글자가 있는 세계에서는 빈 열 삭제도 불가능하다. 동시에 쓰는 사용자의 좌표와 viewport를 같은 변환으로 옮기지 않으면 strip 모델 역시 잘못된 셀에 입력한다. 따라서 resize에는 epoch와 원자적 변환, 이전 epoch 쓰기의 명시적 거절 또는 변환 규칙이 필요하다.

초기 정수 모델에서 안전한 축소는 제거할 영역이 비어 있는지 확인한 뒤 실행한다. 내용이 있으면 축소를 보류한다. 단순 modulo로 덮어버리는 것은 scavenger에 의한 명시적 정리와 다르며 조용한 데이터 손실이다. 성장 시 경계 문장 단절은 현재 모델의 알려진 한계로 남긴다.

## GPS에서 무엇을 안정적으로 유지할 것인가

현재 세계 폭에 정규화한 경도 `floor(((lon+180) mod 360)/360 * width)`를 사용하면, 32→40 확장에서 경도 7개 샘플 중 6개가 다른 셀에 도착했다. 기존 문자가 정수 주소에 남는 모델과 조합하면 같은 GPS로 돌아가도 예전 글 앞에 도착하지 않을 수 있다. 이는 계산 오류가 아니라 서로 다른 안정성 선택의 충돌이다.

- **현재 크기 정규화**: 세계 전체를 지리에 대응시킨다. resize마다 GPS 착지가 변한다. MVP에 쓸 수 있지만 영구적 장소 주소라고 약속해서는 안 된다.
- **고정 atlas anchor**: GPS를 변경되지 않는 기준 셀에 연결한다. 세계가 커져도 재방문이 안정적이지만 기존 영역에 착지가 집중되고 새 공간은 지리적으로 직접 접근하기 어렵다.
- **지리 anchor + 가변 ID 격자**: anchor ID와 새로 삽입된 셀의 보간을 따로 유지한다. 재방문과 확장 여지가 있지만 anchor 삭제 정책, 극점 및 경계 처리까지 실험해야 한다.

등거리 원통 도법의 셀 면적은 위도 0°, 30°, 60°, 80°에서 적도 셀의 약 1, 0.866, 0.5, 0.174배다. `sin(latitude)` 기반 등적 도법은 이 면적 차이를 줄이지만 실제 이동 거리와 화면 이동의 비례 관계를 바꾼다. Web Mercator는 고위도 clipping을 추가한다. 지구는 구면이고 세계는 torus이므로 북극과 남극의 접합은 어떤 단일 직사각형 투영에서도 지리적 이웃 관계를 완전히 보존하지 않는다.

정확한 위·경도는 브라우저에서만 투영하고 서버에는 양자화된 셀을 보낸다. 서버가 정밀 좌표를 받지 않아도 착지 셀은 대략적인 지역을 드러낸다. 권한 거절·시간 초과 시 명시적 공동 출발점으로 진입할 수 있어야 한다. 위치 버튼은 GPS를 다시 읽고, 오래된 최초 위치를 현재 위치라고 사용하지 않는다.

## 동시 덮어쓰기의 실질적 대안

| 모델 | 실험상 기대 | 비용·반례 |
| --- | --- | --- |
| 서버 수신 순서 | 연결된 사용자에게 하나의 순서와 명확한 현재 셀 제공 | 단일 writer 가용성·지연 편향. ACK와 snapshot 재접속이 필요 |
| 클라이언트 timestamp LWW | 서버 없이도 합칠 수 있음 | 미래 시계가 오랫동안 승리. 물리 시각 대신 논리 시계·동점 규칙을 써도 사용자에게 승패를 설명해야 함 |
| 셀별 다중값 register | 경쟁한 글을 모두 증거로 보존 | 현재 셀에 무엇을 보여줄지 추가 규칙 필요. 한 셀의 표시 문자가 복수가 되어서는 안 됨 |
| compare-and-swap 일반 입력 | 사용자가 본 버전만 수정 | 자유롭게 덮어쓰는 경험에서 지연이 크면 입력 거절이 잦음. 일반 쓰기보다 scavenger 삭제에 적합 |
| 지역별 lease/권위 | 같은 지역의 쓰기를 근처 서버에서 처리 | 사용자의 이동·토러스 경계·resize 때 권위 이동 및 split brain 처리 필요 |

현재 목표는 연결된 두 사용자다. 서버 순서 + 보존된 출처/변경 묶음은 가장 작은 검증 가능한 출발점이다. 오프라인 입력을 조용히 재생하면 재접속한 사용자가 최신 글을 과거 의도로 지울 수 있으므로, MVP에서는 연결이 끊긴 동안 전송을 막고 snapshot을 받은 뒤 다시 쓴다. 오래된 scavenger 삭제는 반드시 셀 버전 조건으로 거절한다.

## 다음에 반증할 가설

1. **빈 strip 수술이 사용자 혼란을 줄인다.** 경계에 있는 두 사용자가 글을 쓰는 도중 같은 크기 변화를 두 모델로 재생한다. 글자쌍 인접성 손실, cursor와 본인 글의 거리 변화, 오래된 epoch 입력 거절 수를 비교한다. 전세계 random occupancy에서 빈 strip이 존재하는 비율도 측정한다.
2. **전역 밀도만으로 성장하면 지역 혼잡을 놓친다.** 동일한 사용자 수를 한 셀 주변/고르게 분산한 두 패턴으로 배치한다. 화면 내 커서 중첩률과 세계 면적 변화를 비교한다. 면적만 키우고 사람을 그대로 두면 혼잡이 실제로 풀리는지 확인한다.
3. **고정 atlas가 장소 재방문에는 더 낫다.** 같은 GPS의 사용자가 세 번의 resize 전후에 재접속하여 자신이 쓴 글까지 이동해야 하는 셀 수를 비교한다. 세계 전체 면적 중 지리에서 직접 도달 가능한 비율도 함께 측정한다.
4. **수신 순서와 명시적 pending 상태면 덮어쓰기 승패를 이해할 수 있다.** 두 클라이언트에 0/200/800ms 지연과 연결 단절을 주고 동일 셀을 쓴다. ACK 뒤 모든 화면의 최종 버전 일치, 재접속 후 유령 재전송 부재, 사용자에게 표시한 보류/실패 상태를 확인한다.

위 1~4는 아직 실행하지 않은 후속 실험이다. 현재 실행 증거는 `experiments/topology.mjs`의 결정적 좌표 변환 반례뿐이다.
